# SubAgent 重构任务拆分

日期：2026-09-12。状态：用户随后明确要求使用 `implement` 完成；已按依赖实施，最终验证结果与未验证范围已记录。任务仍仅保存在本地，未发布到外部平台。实施证据与验证限制见 [验收报告](acceptance.md)。

依据：[定稿规格](../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[源码研究](../../docs/research/subagent-codex-refactor-2026-09-12.md)。规格中“不拆任务”的表述记录上一阶段范围，本轮明确授权本地拆分；产品决定和实现边界保持原样。

## 拆分与交付

1. **[空回答重试保留已执行成果](issues/01-retry-with-history.md)**。Blocked by：无。交付：用户遇到子模型空回答时，系统保留已经执行的工具和上下文，只恢复模型回答步骤，避免同一修改再次发生。这是异步改造前的独立修复，继续沿用现有用户入口。

2. **[异步派工并查看独立子任务](issues/02-async-launch.md)**。Blocked by：01。交付：主代理启动一个子代理后立即得到可查询标识，并能继续其他工作；当前对话展示该子代理的名称、任务、状态和完整结果。建立最窄的创建到完成路径，复用现有执行循环。

3. **[并发名额满时明确拒绝派工](issues/03-capacity-admission.md)**。Blocked by：02。交付：用户能预测同时运行的子任务数量；容量不足时获得明确反馈，没有隐藏排队或等待名额消耗整任务超时的问题。

4. **[单独停止子代理或停止整个协作](issues/04-targeted-stop.md)**。Blocked by：02。交付：用户和主代理能停止指定子代理；主对话停止按钮终止当前整个协作。界面准确区分正在停止、停止失败和已经中断，已完成成果保留。

5. **[途中补充信息和空闲留言可追踪](issues/05-durable-messages.md)**。Blocked by：02。交付：用户在子代理面板发送补充要求，主代理也可投递信息。运行中在约定边界接收；空闲时只保存留言。发送者能看到受理、待消费、已消费或拒绝状态。

6. **[沿历史继续子代理并防止重复执行轮次](issues/06-continue-agent.md)**。Blocked by：04、05。交付：用户可在空闲或中断后明确继续同一子代理，沿用历史和待消费留言；主代理可交代后续任务。新建和继续保持不同操作，用户停止不会被自动重试抵消。

7. **[逐个收集结果并等待必要依赖后收尾](issues/07-parent-result-collection.md)**。Blocked by：04。交付：主代理先处理已完成的子结果，等待必要依赖期间仍响应用户；所有依赖达到完成、失败或中断后汇总，不因最慢任务阻塞整批，也不在空闲时被子结果自动开新轮。

8. **[重启保留工作并显式继续未知结果调查](issues/08-restart-recovery.md)**。Blocked by：06。交付：应用退出或崩溃后，用户仍能查看历史、成果和待消费留言。未结束执行标记中断，明确继续才运行；无法确认是否生效的工具先核查，不自动重放。

9. **[保存或投递故障后仍能恢复唯一结果](issues/09-recover-result-delivery.md)**。Blocked by：07、08。交付：子任务已完成但父方暂时不能接收时，结果可靠保留并可重新投递。写入故障和应用重启不会导致只有完成提示而没有成果，或同一结果重复进入父模型。

10. **[重开面板恢复状态并核查完整成果](issues/10-reconnect-history.md)**。Blocked by：06。交付：用户关闭面板、切换对话后再打开，能恢复子代理的状态、消息和完整历史；摘要保持简洁，详情可核查全部成果。

11. **[切换内置入口并保留旧历史和外部 CLI 行为](issues/11-compatibility-cutover.md)**。Blocked by：03、09、10。交付：在完整新能力就绪后，让内置子代理入口统一使用新控制接口。用户继续查看旧卡片，外部 CLI 保持原有能力，所有调用最终共用一套内置执行实现。

12. **[完成跨功能验收并记录剩余限制](issues/12-integrated-acceptance.md)**。Blocked by：11。交付：验证整套协作行为在同一构建中成立，提供可核查的验收报告。此项是集成收尾，不承接前面任务遗留的功能或用替身测试冒充真实端到端完成。

## 依赖顺序

依赖仅表示技术前置，不等于开工授权。以下列出直接阻塞边，前置的前置不重复列出。任务 01 是独立行为修复；02 增加最窄异步路径；03—10 每项沿相关控制入口、执行/记录、界面和验证贯通；11 完成兼容切换；12 专门验证组合行为。每项应在一个新上下文中可完成，若落地探索证明范围过大，先更新本地拆分，不静默扩大任务。

| 任务 | 直接依赖 | 为什么需要 |
|---|---|---|
| 01 | 无 | 现有循环可独立修复重复副作用问题。 |
| 02 | 01 | 异步路径复用已修正的执行循环。 |
| 03 | 02 | 需要真实异步受理与执行资源归属。 |
| 04 | 02 | 需要身份、执行句柄及可查询状态。 |
| 05 | 02 | 需要独立执行、历史记录和控制入口。 |
| 06 | 04、05 | 继续须遵守用户停止状态，并消费待处理留言。 |
| 07 | 04 | 收尾必须处理真实中断及父失败后的取消传播。 |
| 08 | 06 | 需要完整的明确继续流程；保留工具历史的 01 已被传递依赖覆盖。 |
| 09 | 07、08 | 需要父方接收协议与真实重启读取能力。 |
| 10 | 06 | 面板恢复需要可呈现的消息、停止与新执行状态。 |
| 11 | 03、09、10 | 容量、可靠恢复和完整界面均就绪后才能切换入口。 |
| 12 | 11 | 完整新路径切换后执行组合验收。 |

从技术上，01 完成后做 02；02 完成后 03、04、05 可以分别推进；04 完成后可做 07，04/05 都完成后可做 06。具体并行执行仍需避免共改同一代码；本轮不分派任何执行代理。

每项独立验证并保持已有路径可用；未完成全部基础承诺前，不把开发入口作为已交付功能。不能把可靠保存、基本取消或权限隔离全部推迟到最后。最后验收也不能替代各项的行为测试。

## 审阅与启动边界

拆分阶段曾仅授权本地草稿。后续 `implement` 指令已授权实施及技能要求的本地提交；仍不创建 GitHub issue 或发布任务。各任务的详细验收采用报告中的证据和限制，不以批量勾选代替测试。

测试接缝已经由规格给出：共享子代理控制接口、真实调度与执行循环、可控 provider/工具，以及真实文件存储。后续实现逐条验证，报告清楚区分确定性验证和实际 provider 端到端验证。实施阶段已运行产品测试，具体命令、结果及实际 provider 验证范围见验收报告。
