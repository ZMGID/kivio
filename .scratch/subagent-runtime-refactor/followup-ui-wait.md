# SubAgent 试用反馈修复

日期：2026-09-13。基线：48847685。依据用户对话反馈及三张截图；仅本地修改和提交。

## 观察与修复

试用记录中两个子代理均完成，并消费了中途补充信息。主代理却连续调用 21 次 wait，每次只耗时数毫秒；请求的长超时不等于实际等待时长。最后一条回复仍是准备核对后再给结论。进度更新与结果共用唤醒通道，是等待反复提前返回的原因。

- 输入框旁仅显示子代理图标和数量，点击打开右侧任务页。
- 任务页顶部显示主代理模型、运行状态及停止整个协作；下面按行显示子代理。详情保留补充信息、停止、继续及消息回执。
- 任务说明和完整历史默认折叠，长说明限定高度，任务页负责纵向滚动。结果使用现有 Markdown 渲染器。普通后台命令仍显示在任务页内。
- 输入框标记与任务页共享每 2.5 秒一次的轻量列表读取；详情仅按选中记录的版本更新。关闭详情不停止子代理。
- 模型 wait 使用单独的终态通知及按对话维护的结果位置，进度不会唤醒它。回执返回实际 waited_ms、结束原因和封顶后的 timeout_ms。
- 模型控制回执不再重复完整提示词和执行历史；get 仍可取结果，桌面详情保持完整读取。
- 收到子代理结果后的 synthesis 明确要求当前轮给出结论。对于本次观察到的短暂承诺式中英文回复，仅补写一次最终回答，不重跑工具；再次出现同类回复时返回失败，不能算完成。此检测针对已知措辞，并不保证能识别所有语义上不完整的答案。
