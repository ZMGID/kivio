# 04: 单独停止子代理或停止整个协作

**What to build:** 用户和主代理能停止指定子代理；主对话停止按钮终止当前整个协作。界面准确区分正在停止、停止失败和已经中断，已完成成果保留。

**Blocked by:** 02：异步派工并查看独立子任务

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A11, A13, A15, A25, A28。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A11：停 A 不停 B；从正在停止到已中断必须等待循环和受管理工具清理确认。
- [ ] A13：主停止先封住新增派工，再取消所有已受理子执行；与新派工竞争不漏任务，不影响其他对话。
- [ ] A15：工具终止未确认时保留原因、控制入口和资源归属，不显示已停完；正常退出拒绝新工作并清理受管理 worker。
- [ ] A25、A28（停止部分）：两类调用者使用统一接口，按所属对话和预期执行校验；UI 使用子代理控制路由，不走 shell 停止路由。
- [ ] 已提交终态不会被迟到停止覆盖；保存用户停止原因，供继续规则判断，不自动撤销已有修改。
- [ ] 删除活跃父对话先完成停止，再删除从属记录；停止不能完成时明确反馈，不能遗失资源控制权。

## Verification

并行执行 A/B，单独停 A 后 B 完成；再次派工时主停止阻止新增工作并清理全部当前子执行。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
