# 08: 重启保留工作并显式继续未知结果调查

**What to build:** 应用退出或崩溃后，用户仍能查看历史、成果和待消费留言。未结束执行标记中断，明确继续才运行；无法确认是否生效的工具先核查，不自动重放。

**Blocked by:** 06：沿历史继续子代理并防止重复执行轮次

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A20, A22。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A20：用真实文件存储重启管理模块，未终态执行标记进程中断；历史、完成成果与未消费消息可见，无自动模型或工具调用。
- [ ] A22：工具开始前保存意图、结束后保存结果；在外部操作生效但完成记录未写入的故障窗口，恢复显示结果未知。
- [ ] 明确继续以新执行读取中断位置、已完成和未知工具记录；未知操作先核查外部状态，不能以缺少成功记录推断未执行。
- [ ] 保存意图失败时不开始副作用；已记录完成的工具不因恢复而重放，停止不撤销修改。
- [ ] UI 呈现中断原因、未知工具结果和继续操作；仅复原历史不显示仍运行，不承诺任意外部副作用恰好一次。
- [ ] 覆盖正常退出后的读取和崩溃窗口；版本化记录缺少可选字段可降级读取，缓存淘汰不删除可继续历史。

## Verification

在工具结果保存前注入故障，重启看到未知结果与待消费留言；明确继续后先检查先前操作。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
