# 09: 保存或投递故障后仍能恢复唯一结果

**What to build:** 子任务已完成但父方暂时不能接收时，结果可靠保留并可重新投递。写入故障和应用重启不会导致只有完成提示而没有成果，或同一结果重复进入父模型。

**Blocked by:** 07：逐个收集结果并等待必要依赖后收尾；08：重启保留工作并显式继续未知结果调查

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A08, A18, A30。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A30：终态、完整结果引用与待投递记录通过原子提交或可恢复写入保持一致，故障后得到一致状态。
- [ ] A18：父方按执行标识去重，接收记录与上下文追加一致；父方接收前后崩溃并重投递，不重复注入结果。
- [ ] A30：覆盖保存前后、投递前后与父方确认前后的故障点；结果存在不依赖 UI 或通知成功。
- [ ] A08：消息受理/消费写入故障跨实际重启仍满足已受理不丢失、已消费不重复追加；不能先删信箱再保存上下文。
- [ ] 查询和 UI 在未可靠完成时展示真实保存/恢复错误，修复或重试后可读取完整结果；不自动重跑已经结束的子任务。

## Verification

阻断完成通知并重启，恢复投递一次完整结果；重复重投不再次进入父模型历史。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
