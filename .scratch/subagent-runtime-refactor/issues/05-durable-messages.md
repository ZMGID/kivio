# 05: 途中补充信息和空闲留言可追踪

**What to build:** 用户在子代理面板发送补充要求，主代理也可投递信息。运行中在约定边界接收；空闲时只保存留言。发送者能看到受理、待消费、已消费或拒绝状态。

**Blocked by:** 02：异步派工并查看独立子任务

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A05, A07, A08, A25。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A05：当前模型请求或工具结束后的下一次输入构建前追加消息一次，保留已执行成果，不为普通消息打断请求。
- [ ] A07：与完成竞争时，收尾前受理的信息进入当前执行，收尾后作为空闲留言保存并明确回执，没有静默丢失。
- [ ] A08：可靠保存后才确认受理，保存失败明确拒绝；重建存储读取实例后仍能查询成功受理的消息。
- [ ] 消息标识去重、顺序和来源持久保存；上下文追加与消费标记一致；用户明确纠正不会伪装成主代理指令。
- [ ] A25（消息部分）：不同父对话同名子代理不会互相收信；越界、缺失或容量不足明确拒绝。
- [ ] 空闲留言不调用模型，查询可见待消费信息；应用重启和明确继续的完整流程由 06、08 补齐。

## Verification

长工具期间发送补充要求，观察待消费到已消费；任务完成后留言仍不触发模型。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
