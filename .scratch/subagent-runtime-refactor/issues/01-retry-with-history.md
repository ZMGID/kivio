# 01: 空回答重试保留已执行成果

**What to build:** 用户遇到子模型空回答时，系统保留已经执行的工具和上下文，只恢复模型回答步骤，避免同一修改再次发生。这是异步改造前的独立修复，继续沿用现有用户入口。

**Blocked by:** None（无技术前置；审阅通过且用户授权实现后才可开始）

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A21。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A21：可控模型先调用一次写入工具再返回空回答，恢复后写入计数仍为一次，模型可读取此前工具结果。
- [ ] 空回答、模型错误与真正完成分别呈现；重试有边界，耗尽时明确失败，不重建初始任务重新执行。
- [ ] 通过现有公开调用路径和真实执行循环验证，原有正常结果、用量与错误呈现保持可读。

## Verification

展示一次工具修改、一次空回答及恢复后的结果，核对修改只发生一次。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
