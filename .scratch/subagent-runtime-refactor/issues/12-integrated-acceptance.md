## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] 逐项记录 A01—A30 的测试依据、结果及未验证限制；缺失项不能仅因任务已勾选而标通过。
- [ ] 组合验证：启动→补充→单独停止→继续→结果收集，以及退出/崩溃→读取→明确继续→结果去重。
- [ ] 重点回归跨任务边界：A12 旧停止与新执行，A14 用户停止与父方派工，A15 退出与工具清理，A23 清理与容量释放，A18 多轮结果去重。
- [ ] 运行项目要求且与改动相关的检查；复用生产控制接口和真实循环，UI 检查操作及重连，不新增复制实现的 shim。
- [ ] 报告分别列出确定性单元/集成测试、真实存储恢复和实际 provider 端到端验证；后者未执行时明确说明，不能引用旧 32 项测试代表新规格通过。
- [ ] 确认无超出规格的一层以上派工、隐式恢复、自动 worktree 或冻结暂停承诺；任何未通过验收继续列为未完成，不部署。

## Verification

演示完整用户流程并逐项展示验收证据与仍未验证的环境限制。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
