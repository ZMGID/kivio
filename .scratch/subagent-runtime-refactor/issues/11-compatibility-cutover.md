# 11: 切换内置入口并保留旧历史和外部 CLI 行为

**What to build:** 在完整新能力就绪后，让内置子代理入口统一使用新控制接口。用户继续查看旧卡片，外部 CLI 保持原有能力，所有调用最终共用一套内置执行实现。

**Blocked by:** 03：并发名额满时明确拒绝派工；09：保存或投递故障后仍能恢复唯一结果；10：重开面板恢复状态并核查完整成果

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A25, A27, A28, A29。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A29：旧历史可读，无完整子历史时不显示继续；不迁移实际用户数据，不改写外部 CLI 控制路径。
- [ ] A28：模型工具与用户操作均经过统一控制接口，停止、消息、继续无重复状态源或 shell 路由。
- [ ] 若保留旧阻塞契约，只作为启动加等待适配；确认调用者迁移完成后移除重复 worker 路径，正常验证路径启用新入口。
- [ ] A25、A27：全操作复核父对话隔离、角色模型配置和当前授权，禁止跨对话控制或子代理再次派工。
- [ ] 默认值与用户已有配置兼容，旧回执和新独立结果可同时阅读；保留明确回退路径，切换前相关回归通过。
- [ ] 此任务只交付代码内入口切换与验证，不包含发布、部署或用户数据迁移。

## Verification

同一环境打开旧卡片、新建并继续新子代理，再运行一条外部 CLI 对话，逐项核对能力与控制路由。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
