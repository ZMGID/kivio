# 02: 异步派工并查看独立子任务

**What to build:** 主代理启动一个子代理后立即得到可查询标识，并能继续其他工作；当前对话展示该子代理的名称、任务、状态和完整结果。建立最窄的创建到完成路径，复用现有执行循环。

**Blocked by:** 01：空回答重试保留已执行成果

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A01, A03, A25, A28。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A01：屏障阻住子模型时启动回执已返回，父方可执行独立工作，子任务随后独立完成。
- [ ] A03：稳定受理键重复提交只创建一个子代理及一次初始执行；持久受理后才回执，回执丢失可查询。
- [ ] A25（创建/查询部分）：记录所属父对话及独立执行标识，越界或不存在目标明确拒绝，同名不混淆。
- [ ] A28（创建/查询部分）：模型入口与桌面查询使用同一控制接口，UI 区分受理成功与任务完成。
- [ ] 沿用文件式持久化，保存身份、历史、终态与完整结果；管理模块持有执行句柄，初版即保留基本并发限额与取消清理，不能放任孤立执行。
- [ ] 新建上下文只含角色、技能、任务及显式材料；保存配置，沿用父工作目录和授权，只允许一层派工。
- [ ] 异步入口在整体验收前保持显式开发验证入口，生产旧入口可用；不为未完成的继续、消息或恢复能力展示可用按钮。

## Verification

派出一个受屏障控制的子任务，主代理做另一项工作，再在详情中看到子任务结果。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
