# 10: 重开面板恢复状态并核查完整成果

**What to build:** 用户关闭面板、切换对话后再打开，能恢复子代理的状态、消息和完整历史；摘要保持简洁，详情可核查全部成果。

**Blocked by:** 06：沿历史继续子代理并防止重复执行轮次

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A19, A26。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A19：按所属对话、子代理、执行标识与事件序号恢复快照和增量；重连期间无状态倒退或丢失。
- [ ] A19：事件缓冲不足回退读取完整快照；关闭视图只退订，不停止应用内仍运行的子任务。
- [ ] A26（结果展示部分）：卡片短摘要不截断持久完整结果，详情显示角色/模型、任务、进度、用量、来源和完整历史。
- [ ] 重开面板后正确显示待消费/已消费、正在停止与可用操作；前一执行迟到事件不能覆盖当前执行。
- [ ] 历史按需加载、查询缓存有界，不因旧的进程内数量限制删除历史；对旧记录不可用的能力明确降级。

## Verification

任务运行时关面板，消息消费或任务完成后重开；再模拟事件缓冲过期，仍恢复完整状态。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
