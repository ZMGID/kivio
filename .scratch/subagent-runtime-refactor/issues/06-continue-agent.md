# 06: 沿历史继续子代理并防止重复执行轮次

**What to build:** 用户可在空闲或中断后明确继续同一子代理，沿用历史和待消费留言；主代理可交代后续任务。新建和继续保持不同操作，用户停止不会被自动重试抵消。

**Blocked by:** 04：单独停止子代理或停止整个协作；05：途中补充信息和空闲留言可追踪

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A04, A06, A12, A14, A26, A27。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A04：并发继续请求不会产生两个循环；空闲时创建新执行标识，运行中后续任务作为当前执行的补充，回执指向实际执行。
- [ ] A06：空闲留言不启动，明确继续读取原历史与未消费消息；继续与完成竞争仍有明确执行归属。
- [ ] A12：过期停止请求不影响新执行，旧事件不覆盖新状态；迟到停止不能抹去已完成结果。
- [ ] A14：用户停止后主代理不能立即自动重试；新的用户继续指示或用户允许后的明确继续才能解锁。
- [ ] A26（上下文/用量部分）：正确加载压缩历史，不拼回压缩前内容，不重复计算此前用量。
- [ ] A27：保留角色及模型选择，重新检查当前权限与凭据；撤销授权不能复活，不可用配置明确失败，新建仍为独立上下文。
- [ ] UI 明确区分补充、留言和继续；继续是新执行，不承诺恢复进程现场或动态修改配置。

## Verification

完成任务后留言并继续一次，再停止一次后继续；展示历史沿用、执行标识变化和过期停止被拒绝。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
