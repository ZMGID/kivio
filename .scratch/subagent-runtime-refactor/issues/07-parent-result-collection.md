# 07: 逐个收集结果并等待必要依赖后收尾

**What to build:** 主代理先处理已完成的子结果，等待必要依赖期间仍响应用户；所有依赖达到完成、失败或中断后汇总，不因最慢任务阻塞整批，也不在空闲时被子结果自动开新轮。

**Blocked by:** 04：单独停止子代理或停止整个协作

**Status:** implemented — 依据后续 `implement` 指令实施；验证结论及未验证范围见 [验收报告](../acceptance.md)。

**Spec acceptance:** A02, A09, A10, A16, A17, A18。部分覆盖的边界以各验收条目和总览映射为准。

依据：[定稿规格](../../../docs/prd/subagent-runtime-refactor-spec.md)、[ADR-0005](../../../docs/adr/0005-subagents-retain-identity-across-tasks.md)、[领域术语](../../../CONTEXT.md)。

## Acceptance criteria

以下保留原验收清单；逐项证据统一记录在验收报告中，未做实际 provider 端到端验证的条目不据此宣称实测通过。

- [ ] A02：A 先完成即可到达父方，B 继续运行；父方按所依赖执行标识收集，而非按可复用名称。
- [ ] A09：检查活动与建立订阅之间不漏唤醒；等待使用游标，不吞消息或反复调用模型轮询。
- [ ] A10：等待超时和用户输入只结束等待，不取消子执行；父执行能继续响应用户。
- [ ] A16：未终态依赖阻止正常收尾；失败/中断带原因进入汇总，不无限等待成功答案。
- [ ] A17：父轮已终态仍保存子结果，空闲父方不自动调用模型；不可恢复父错误停止仍活跃的当前子执行。
- [ ] A18（正常投递部分）：重复结果按执行标识去重，乱序状态不能把已完成改回运行中；终态与待投递结果从本项起可靠记录，故障恢复由 09 验证。
- [ ] 用户可在时间线上区分启动回执、子结果与主代理最终总结，事件不写入已封口父轮。

## Verification

一快一慢两个子任务，先收到快任务结果；等待时用户插话，再让慢任务失败，主代理说明缺口并正常收尾。

通过用户与模型共享控制接口检验可观察行为；涉及 UI 的行为须有操作验证，涉及持久化的行为须用真实存储验证。只实现本项明确范围，公共行为遵循规格，不能用临时实现替换既定承诺。
