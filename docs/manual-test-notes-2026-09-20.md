- **现象**：启动 Kivio 时，右侧栏会闪一下。

- **处理决定**：用户确认只在开发版出现，要求不修复；已撤回本次针对启动闪烁的改动。
- **状态**：仅记录，暂不处理。

## 2. 频繁切换对话时希望保留近期对话

- **类型**：优化想法。
- **使用场景**：同时处理几个任务，需要在对应的对话之间频繁切换。
- **使用感受**：每次切回对话都像是重新加载，切换过程需要等待；频繁切换时体验不好。
- **初步想法**：为近期对话增加缓存，暂定保留 3 个对话。
- **待确认**：当前是否确实每次重新加载、具体加载耗时，以及“3 个”是否为最终数量。
- **状态**：本轮缓存实现已按用户要求回退；保留反馈，暂不继续处理。

## 5. 关闭窗口或注销后，定时自动化是否继续运行

- **类型**：使用疑问与可靠性关注。
- **疑问**：日常关闭 Kivio 页面后，定时任务还能否按时执行；如果系统注销，会不会失效。
- **代码核对**：默认关闭聊天窗口会销毁该窗口，但 Kivio 进程仍留在托盘，进程内的定时调度器继续运行。真正退出 Kivio 或操作系统注销后，进程停止，定时任务不能在那段时间运行。
- **到点后的流程**：调度器找到启用且到期的流程并记下触发时间；执行器检查是否可启动，创建运行记录，然后从定时触发节点沿连线执行后续节点。节点输出传给下一节点，状态和结果写入运行历史；只有流程包含通知节点时才发送系统通知。
- **需关注的边界**：同一自动化已有运行，或同时运行的自动化达到 4 个上限时，本次启动会失败；调度器已记下触发时间，目前没有对这次失败自动重试。
- **边界**：每日/工作日任务只在目标时刻后的约 2 分钟窗口内触发，超过窗口不会补跑；间隔任务重启后可依据上次触发时间再次检查，但首次启用会先计时。
- **实机验证（2026-09-20 02:44，本地时间）**：在运行中的开发版创建并启用临时“每 1 分钟触发 → 设置固定输出”流程，关闭聊天窗口后确认 Kivio 进程仍在。到点产生一条 `origin: schedule`、`status: success` 的运行记录；`trigger.schedule` 与 `action.set` 均成功，输出为 `{"smoke":"live-schedule-ok"}`。随后删除临时自动化并重新打开聊天窗口。
- **验证范围**：确认关闭聊天窗口、应用留在托盘时，间隔定时任务可触发并完成；没有测试 Windows 注销、电脑休眠、每日/工作日触发或通知节点。
- **证据**：[本次运行记录](manual-test-assets/automation-schedule-smoke-run.json)。
- **状态**：实机验证通过；未修改实现。

## 6. 已生成文件在后续回复中的引用显示“文件不可用”

- **类型**：文件引用问题。
- **现象**：同一段对话的较早回复表示已经整理出 `提示词资源地图.md` 和 `助手提示词模板.md`，并显示了文件引用；后续回复再次引用这两个文件时，界面将其标为“文件不可用”。
- **发生顺序补充**：用户可能曾停止生成，随后又发送新消息；这是否导致引用失效尚不确定。
- **相关对话**：Kivio 开发版中标题以“我需要你收集现在各个流行的提示词”开头的对话。
- **期望**：已生成并可访问的文件，在后续回复中仍能正确引用和打开；若文件确实不存在，界面应准确说明原因。
- **截图**：[后续回复显示文件不可用](manual-test-assets/generated-file-reference-unavailable.png)、[较早回复中的文件引用](manual-test-assets/generated-file-reference-earlier.png)。
- **排查结果**：两个文件当时都已落盘，对应的 artifact ID 和路径仍保存在被停止的上一轮工具记录中。后续回复的 Markdown 引用了这些 ID，但界面只用当前消息的 artifact 列表解析引用，因此误显示“文件不可用”。停止生成不是文件丢失的原因。
- **修复**：消息列表从当前对话已保存的消息中建立 artifact ID 索引；渲染每条回复时，只补入该回复实际引用、且当前消息未携带的旧 artifact。对话切换后不会沿用上一条对话的索引。
- **验证**：跨轮引用的回归测试修复前失败、修复后通过；相关 `MessageList`、`MessageBubble`、`MessageGroup` 测试，以及 TypeScript、ESLint、架构检查均通过。用户随后确认原始使用场景已恢复正常。
- **状态**：已修复并由用户确认。
