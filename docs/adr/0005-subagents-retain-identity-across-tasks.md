# 子代理保留身份与历史，任务执行独立于派工回执

2026-09-12，在 SubAgent 重构讨论第一轮中确认：子代理完成工作后保留历史，允许继续同一个子代理，也允许为新任务创建新的子代理；完成后释放执行资源。主代理和用户都可以管理子代理。主代理默认收齐当前任务所需的子任务结果后再结束本轮，子任务运行期间仍可开展其他工作、接收用户消息。

此决定针对 Kivio 内置运行时，随后已按用户 `implement` 指令实施。依据见 [源码研究](../research/subagent-codex-refactor-2026-09-12.md)。

同日定稿时确认其余三项：普通补充消息在下一个允许边界处理，明确停止或改方向才中断；主对话停止整个当前协作，子代理卡片只停止对应分支；历史、结果与已受理消息跨重启保留，未完成执行标记中断，明确继续后才运行，不自动重跑。

完整行为、工程范围与验收以 [SubAgent 重构规格](../prd/subagent-runtime-refactor-spec.md) 为准。定稿阶段仅保存本地；随后实施仍不向外部平台发布任务。

## 取舍

- 不采用严格一次性、完成后只能新建的对象模型：继续调查或修改时，需要保留前次工作上下文。
- 不把子代理操作限定为通过主代理转达：用户应能在任务面板直接查看、补充信息、停止指定子代理。
- 不以整个子任务执行作为启动工具的等待时长：派工后父代理可以继续工作，最终汇总仍需等待所依赖的结果。
- 默认不采用主代理先结束、再由子结果自动开启父轮的流程。是否提供显式后台任务模式，另行讨论。
- 普通留言不隐式启动空闲子代理；补充信息与明确继续分别表达，避免意外执行。
- 主停止覆盖当前协作，单独停止保留其他分支的工作；中断保留已发生的修改，不承担撤销语义。
- 持久保存已受理消息增加存储与恢复成本，但能兑现重启后继续的承诺；恢复历史不等于自动重放工具，也不承诺恢复进程现场。

## 后续影响

子代理身份、一次子任务执行和资源占用必须分别表达；子任务完成不能直接表示删除历史。界面与模型对同一子代理的操作应遵循相同语义。

六项产品决定均已确认。上下文继承、并发、文件隔离及测试接缝由定稿规格限定首版范围；研究报告中的其他候选建议不自动成为需求。规格定稿不代表运行时已具备这些能力。
