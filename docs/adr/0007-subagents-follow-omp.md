# 子代理改用 OMP 设计

2026-11-05，用户确认：内置运行时的子代理整体改为 oh-my-pi（OMP，`can1357/oh-my-pi` commit `5dec65e`，MIT）的设计，原有实现放弃，不迁移、不兼容。实施计划见 [OMP 子代理三步计划](../prd/omp-subagents-plan.md)。

本决定取代 [ADR-0005](0005-subagents-retain-identity-across-tasks.md)。主要变化：

- 派工为批量 `task`，异步返回 id；结果自动送达父代理。父代理空闲时，送达结果会开启新的一轮；用户手动中断后只记入上下文。
- 子代理之间、父子之间通过 `write agent://<id>` 互发消息（IRC）。发送不等待回复；运行中的收件方在步骤边界接收，空闲的被唤醒开一轮，parked 的先复活。普通消息因此会启动空闲子代理。
- 子代理状态为 running / idle / parked / aborted；空闲 7 分钟释放会话并保留记录，发消息或打开时复活；kill 写入 tombstone。
- 子代理内需要审批的工具强制放行，不再询问用户。
- `wait` 无参数，等待自己名下的作业或自己发出消息的回复。

## 取舍

- 接受"父空闲时自动开轮"：避免主代理为等子代理而阻塞整轮；代价是可能出现无用户输入的回合，需与用户输入共用同一条空闲预留路径。
- 接受子代理审批强制放行：子代理没有界面可确认；风险由用户承担。
- 放弃 ADR-0005 的持久执行恢复与"留言不唤醒"语义，换取与 OMP 行为一致。

## 后续影响

代理状态、单次运行状态与后台作业状态必须分别表达，不得合并。提示词以 OMP 原文为准。
