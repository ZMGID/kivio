# Kivio 全项目架构整理规格

状态：第一阶段结构整理已实施；语义一致性、状态所有权与平台验收尚未闭环。日期：2026-09-19。

后续实施与完成条件以 [架构收口规格](./architecture-convergence-spec.md) 为准。复核确认设置保存/合并/跨窗口并发、跨端路由契约、导航竞态和迁移失败处理仍有缺口，AppState 与页面 controller 也仅部分收口；不能将“质量门通过”或“8/8 覆盖”解释为整体架构已经完成。

本规格将全项目架构审查转为可以分批实施、独立验收的工作。实施基线为 `44c60d28097422add2451b7b1a8131471c586292`；实施前已有的本地未提交变更已单独记录并在提交时保留。本文后附本轮实施记录与仍需实机验证的范围。

## 1. 目标与范围

目标是让同一业务规则只有一个权威实现，让状态的生命周期由所属模块控制，并由自动检查约束跨模块依赖。一次配置、会话或外部 CLI 代理变更应主要修改其所属模块及接口测试。

范围包括前端 Chat、设置、Lens、自动化入口、公共展示模块和桌面命令调用；后端设置、运行状态、外部 CLI 代理、聊天持久化，以及它们与 MCP、插件、翻译、截图、窗口生命周期的接口。

保持现有产品行为、存储格式、命令与事件契约。规格明确列出的正确性修复除外。数据库替换、统一所有 CLI 协议、全局状态库替换、新的插件框架、功能扩展、视觉改版均不属于本期。优先沿用既有目录和接口；完成所有权迁移后再决定是否改目录名。

模块划分采用 `codebase-design` 的 Module / Interface / Seam / Adapter 原则：Interface 包含行为、不变量、错误及生命周期；状态藏在 Implementation 内；在实际存在不同实现的 Seam 上使用 Adapter。文件行数与 hook 数是调查线索，不作为质量门槛。

## 3. 必须保留的不变量

1. 导入只建立显示快照和会话绑定，原生会话仍归外部 CLI 代理所有。续聊使用原 CLI 与绑定身份，不能静默切到内置运行时；工作目录与附加目录保持原有不同含义。
2. 一条对话至多归属于一个集或一个项目，二者互斥；保留既有未分组对话。侧栏手动顺序、钉住、历史记录和导入快照不因代码移动改变。
3. 子代理保留身份和历史；继续创建新的执行，普通补充消息不隐式启动空闲执行。正常父轮结束与用户停止协作保持不同语义，重启不自动重跑旧执行。
4. 事件归属继续遵守 conversation、run、generation 和 cursor 等现有标识。不得将多 run 的合法状态简化为全局或单对话一个 `busy`。迟到事件不得覆盖新执行；自然结束只释放本 run，取消对话使对应全部 generation 失效，发送检查与占位保持原子性。
5. 窗口卸载只清理订阅和展示资源，不自动停止后台执行。显式停止、进程退出、超时分别完成已有清理与终态记录；会话进程回收不能抹掉持久会话绑定。启动配置变化触发的进程重建必须保持界面配置和实际配置一致。
6. 设置迁移保留已有隐私和授权语义，例如离线 OCR 不能因默认值回退变为云端处理。密钥不进入日志、测试 fixture 或前端能力摘要。
7. 会话文件仍是真相源，索引保持可重建；保留 keyed lock、revision/CAS、迁移屏障、原子写入及索引锁机制。文件替换保持临时文件写入、同步、原子替换的顺序，不能先删除目标。一次逻辑写入不因拆模块变成多套互相竞争的更新路径。
8. macOS、Windows 的窗口、热键、截图和进程管理差异在平台实现内保留。Chat 与 Lens 保持独立命令和事件生命周期；流式显示、懒加载、虚拟列表和取消能力不因抽取模块退化。清空上下文仍保留时间线，换模型回答仍保留已有回答。

## 4. 模块职责与依赖方向

以下为逻辑结构，路径表示建议落点。单批迁移只移动与该批职责有关的代码。

```text
应用组合根 / Tauri 命令适配层
  ├─ Chat            会话、发送、展示订阅、输入草稿
  ├─ Settings        草稿编辑 → 后端设置权威
  ├─ Lens            捕获、编辑、请求、结果展示
  ├─ Automation      自动化定义与执行入口
  └─ 桌面工具入口     翻译、截图、窗口和热键
         │
         ├─ 领域公开 Interface
         └─ 公共展示 / 生成契约 / 平台 Adapter

Rust 领域 Module
  ├─ settings        schema / migration / canonicalize / persistence
  ├─ chat            runtime / interaction / repository
  ├─ external_agents registry / protocol actors / agent-specific adapters
  ├─ lens            capture / request lifecycle
  └─ mcp / plugins / automation 等现有领域
         └─ 显式依赖 → 文件、进程、事件、网络等既有实现
```

### 4.1 前端

| Module | 状态与行为归属 | 对外 Interface | 禁止事项 |
|---|---|---|---|
| Chat 会话协调 | 当前展示目标、加载、订阅、旧响应隔离 | 展示快照、选择对话、订阅释放 | 读取 Settings UI 内部状态 |
| Chat 输入与发送 | 草稿、附件、提交、steer/follow-up 的既有行为 | 草稿操作、提交与状态反馈 | 将全部 Chat 状态作为参数传入 |
| Settings 编辑 | 编辑草稿、字段错误、保存进度 | 加载/编辑/保存设置 | 独立维护后端默认值或迁移规则 |
| Lens 协调 | 捕获/冻结帧身份、请求取消、编辑和结果状态 | 明确的捕获、请求、取消操作 | 与 Chat 共用无归属的 busy 标志 |
| 公共展示 | 无业务归属的按钮、弹层、图标、国际化 | 纯展示参数与回调 | 导入 Chat/Settings 内部实现 |
| 命令 Adapter | Tauri 调用、传输错误映射和版本解码 | 按领域的操作函数 | 在传输层决定默认模型、授权或运行状态 |
| Route codec | 路由识别、编码和解析 | 纯输入输出；无 DOM 依赖 | 再维护第二份保留路由列表 |

`Chat.tsx`、`SettingsShell.tsx`、`src/Lens.tsx` 保留为组合壳。拆分后的 Module 可以内部使用多个 hook，但调用方不需要知道 effect 执行顺序或替它清理内部资源。

Chat 的设置页面挂载属于应用组合关系，允许组合根导入两个领域的公开入口。通用图标、i18n、展示类型移到 `src/components`、`src/utils` 或有明确职责的公共模块；不强制建立泛用 `shared` 大目录。设置中展示对话库等跨领域页面时，从组合根注入或使用公开入口，避免深层反向导入。

### 4.2 后端

`AppState` 可继续作为 Tauri 管理的应用组合根。领域内部只能获取所需句柄或依赖，不能经 `AppState` 任意读写其他领域字段。过渡期间保留转发入口；同一字段不能在旧、新位置分别拥有一份可变副本。

优先将聊天运行控制、待交互请求、MCP 会话与缓存、Lens 捕获状态、自动化执行分别收回所属 Module。复用已有 `SubAgentManager`、仓储和会话 actor。跨领域操作由应用层协调，不创建第二个全局服务定位器。

每个拥有异步资源的 Interface 必须写明：创建时机、退出时机、取消后等待条件、错误后的回收、事件归属、锁顺序。不得在持有同步锁时等待网络或子进程；拆分保持既有并发许可和锁原子区间。

## 5. 关键行为契约

### C1：设置权威

- Rust settings Module 拥有持久设置的默认值、迁移和规范化。加载、保存、导入及其他写入口最终调用同一条权威路径。
- 前端保留即时格式提示和未保存草稿；传输兼容解码只处理格式，不另作业务决策。页面加载前采用显式 loading 状态；预览 fixture 从同一权威输出生成。
- 保存成功返回最终规范设置，前端以该结果刷新缓存和草稿。失败不得显示保存成功。既有多窗口通知/刷新语义必须保留，不能产生永久失配的缓存。
- 迁移必须幂等，已规范化值再次处理结果不变。先以旧版 fixture 锁定现有行为，再移除冗余实现。
- 验收覆盖：空配置、旧字段、非法枚举、模型失效、保存再加载、同一字段通过不同入口写入。测试不得复制规范算法构造期望值。

### C2：用户问题与外部 CLI 代理协议

- required、字段类型和适用约束必须作为结构信息贯穿 parser、内部模型、Chat 生成契约、前端解析和回答编码。文案中的“必填”不参与逻辑判定。
- 旧版问题没有 required 时保持原有必填行为；MCP form 中不在 `required` 的属性标为可选。可选题允许导航跳过；全部可选的表单允许显式提交空对象。
- 省略、空字符串、`0`、`false`、`null` 必须区分。可选未填属性从响应中省略；不得把 `0` 或 `false` 当作未答，不擅自填 schema default 代替用户回答。
- 后端在编码成功结果前验证必填、数字/整数、枚举等支持的约束。非法数字、非有限数、超出当前无损表示能力的数字不能回退成字符串成功返回；返回可定位字段的错误，保留草稿供更正。
- 先明确当前支持的 schema 子集；不支持的类型、约束或 URL 模式必须走既有明确拒绝路径，不静默降级为不受约束的文本。
- `accept`、`decline`、`cancel` 按各协议方法编码；用户取消、超时、停止或对端退出遵循已定义语义，并保证每个 RPC 请求最多完成一次。不得用一个协议的通用取消对象替代所有协议结果。
- 验收覆盖：混合必填/可选、全可选、跳过中间题、旧历史反序列化、合法/非法数字、枚举、重复提交、提交与取消竞争、方法专属响应。通过真实 parser → payload → UI → encoder 的分层契约 fixture 验证字段不丢失。

### C3：路由

- 只有一个纯 codec 识别路由类型与编码 ID。读取 `window.location` 和记忆最近路由的策略是两个 Adapter，二者依赖该 codec。
- 保留中心页、旧页重定向、onboarding、popout、query 和已编码 ID 的既有行为。是否可记忆由显式策略决定，不把所有合法路由都持久化。
- 非法百分号编码、未知路径返回可处理结果，不能使渲染崩溃。验收对同一输入同时检查导航识别和恢复策略。

### C4：外部 CLI 代理扩展

- 保留并扩展 `RuntimeAgentDef`、`AGENT_DEFS` 和现有协议会话实现。静态定义描述能力，运行时探测提供可用性和动态参数。
- 安装、检测、启动、provider profile、原生会话解析等差异集中到所属代理实现。前端依据能力决定操作可用性；品牌名称、图标与历史 ID 不属于需要消灭的分支。
- 只有实际不同且被多个调用方使用的行为才抽为 Adapter。不得建立包含所有代理操作的巨型 trait，也不要求每个代理重写共用 ACP 实现。
- 新增使用已有协议的代理时，预期只改定义、必要的专用实现、资源和测试。新增协议允许扩充协议分发；不以“只改一个文件”验收。
- 用两个现有且行为不同的代理检验抽取：启动、取消、续聊、能力展示保持不变；支持 steer/follow-up 的代理仅在对端确认后更新已受理状态，拒绝或不支持时保留消息。
- 保持协议 actor 通过 channel 与宿主交互、不持有 `AppHandle` 的现有分工。审批结果对应原始请求；计划批准若需要切换权限，必须在切换成功后放行。

### C5：持久化

- 先通过现有 repository Interface 隔离会话、项目、集、助手、搜索/索引和迁移实现；不建立并行仓储框架，不改变用户数据路径。
- 并发更新继续使用现有锁和 revision/CAS；索引自愈写入必须进入同一索引锁。跨领域修改由现有一致性机制协调，不能因拆文件丢失原子性。
- 旧数据、损坏单会话、索引缺失、并发更新冲突、写失败和重启后重读必须有 fixture 或集成测试。损坏一个会话不得阻断其他会话读取。
- 本期默认无磁盘格式迁移。若实施确需改变格式，先追加独立迁移规格，明确备份、兼容读、回退及失败恢复，不能夹带在模块移动中。

## 6. 分批交付与验收

每批必须能独立审阅，记录旧入口、新 owner、迁移调用方、删去的重复规则、测试与遗留例外。先固定行为，再转移所有权，最后删除兼容转发；不让新旧两套权威长期并存。

| 批次 | 工作与主要文件 | 完成条件 | 依赖 |
|---|---|---|---|
| B0 基线与正确性 | 记录当前 diff；C2 的模型/parser/UI/encoder；V1 握手真实路径测试 | E8/E9 有失败测试并修复，旧历史兼容；V1 给出可达路径和测试结论，不根据疑似问题盲改 | 无 |
| B1 契约与约束 | 扩展现有 exporter/fixtures；设置权威 C1；路由 C3；建立依赖基线 | 设置结果一致、codec 唯一；新违规依赖被 CI 拦截；旧违规按边登记 | B0；设置和路由可分别交付 |
| B2 前端所有权 | Chat 会话协调和输入发送；Settings 草稿；Lens 协调；按领域 API Adapter | 壳组件依赖公开操作；Chat/Settings 不再深层互相导入；晚到响应、卸载、切换不串状态 | B1 中相关契约 |
| B3 后端所有权 | AppState 的领域句柄，优先聊天交互/Lens，再 MCP/自动化 | 迁移领域的状态字段私有；领域实现不持有整个 AppState；停止与并发测试通过 | B0/B1；可与无重叠 B2 工作并行 |
| B4 扩展与存储 | C4 代理适配；C5 持久化内部模块；按归属拆 CSS | 现有协议行为保留；锁和 CAS 测试通过；样式归属明确且跨窗口视觉一致 | B3 中相关句柄 |
| B5 收尾 | 删除已迁移转发、清空违规基线、更新架构说明、跨平台实机验收 | 质量门全部通过；当前批次没有无主兼容层；迁移清单全部闭环 | B0–B4 |

P0 保留给经证据确认的全局不可用、严重数据破坏等紧急问题；当前没有据此确认的 P0。B0 是先处理的工程批次，不等同于故障等级。

## 7. 自动质量门

沿用 `.eslintrc.cjs`、`src-tauri/src/bin/export_chat_protocol.rs`、`src/generated/*` 和 `.github/workflows/ci.yml`。不手工修改生成物来绕过权威定义。

1. **依赖方向**：使用能解析实际 TS import/re-export 的检查，覆盖相对路径、别名、type-only 导入、动态字面量导入及 barrel 转发；公共模块不能导入 feature，feature 不能深层穿透其他 feature。构建模块依赖图检测环，组合根公开挂载单独允许。
2. **渐进基线**：存量违规登记 source、target、原因、目标批次；只允许削减，新增违规必须失败。B5 移除临时例外。检查器使用允许边、禁止边、别名/转发和循环的负向样例证明能拦截。
3. **契约漂移**：继续运行 `protocol:check`，按迁移范围纳入新增字段；共享序列化 fixture 验证 optional/default/null/enum 和错误响应，不只检查类型能编译。
4. **状态封装**：Rust 通过私有字段、模块可见性、窄参数及编译期约束实现；必要时加领域依赖检查。仅将字段包进 `Arc` 或公开子 struct 不算完成所有权收口。
5. **行为回归**：测试外部 Interface 的可观察行为，保留关键并发、取消、异常和持久化场景；不以函数数量、hook 数或测试条数验收。

实施时现有必跑命令：

```sh
npm run lint
npm run typecheck
npm run test
cargo test --manifest-path src-tauri/Cargo.toml
```

按批次先跑受影响用例，合入前执行现有完整质量门。`typecheck` 已含 `protocol:check`。打包和平台相关变更继续遵守现有 packaging/icons/Swift 检查；不为通过检查临时删除测试、放宽断言或扩大忽略列表。

新增架构检查接入现有 CI，并确保它自己的规则或例外文件变化不会被 `docs/**` 的忽略规则漏掉。不得把需要执行的检查配置只放在被忽略的文档目录。

## 8. 端到端验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 内置运行时发送、工具调用、停止、换对话 | 流式与工具结果归属正确；显式停止生效；切换只影响视图 |
| 已导入原生会话续聊 | CLI 身份、工作目录、会话绑定不变，不回退到其他运行时 |
| 外部 CLI 代理启动、提问、退出、steer/follow-up | 依 capability 展示，按对端确认更新状态，异常可观察并回收资源 |
| 设置加载、保存、重开、多窗口刷新 | 返回规范值；保存错误不伪装成功；其他窗口按现有通知一致更新 |
| 项目/集、排序、钉住、搜索 | 归属互斥、手动顺序和定位不变，索引可重建 |
| 路由跳转、旧链接、popout、重启恢复 | 页面与会话 ID 正确，禁止恢复的路由不被恢复 |
| Lens 捕获、取消、重开，以及翻译/截图入口 | 旧请求不覆盖新结果；焦点、热键、离线行为保持 |
| MCP、插件与自动化调用聊天能力 | 授权上下文、取消、错误和工具结果仍由既有 owner 管理 |
| 子代理完成、留言、停止分支、重启、继续 | 符合既有子代理规格，不自动重跑、不丢已受理信息 |
| 重对话和持续流式输出 | 按既有性能基线复测，同机同数据比较；懒加载、虚拟列表、流式刷新无可复现退化 |

Windows 与 macOS 均执行对应平台冒烟；只在一个平台完成时，报告另一个为未验证，不能用源码阅读代替实机通过。

## 9. 实施记录与完成定义

实施期间在每批交付中记录基线提交、工作区已有变更、迁移映射、检查结果和未验证范围。对同一文件的并行工作分配单一 owner；不得覆盖其他在途变更。

完成需要同时满足：E1–E9 对应工作闭环、V1 有验证结论、C1–C5 及端到端矩阵通过、临时依赖例外清空、重复权威删除、既有数据可读且可继续使用。允许保留职责清晰的大文件；不允许用文件搬迁替代行为归属迁移。
