# SubAgent 重构规格：可继续的异步子代理协作

**状态：本地规格定稿，已按后续 `implement` 指令实施。** 日期：2026-09-12。适用范围：Kivio 内置运行时。实施证据与未验证范围见 [验收报告](../../.scratch/subagent-runtime-refactor/acceptance.md)。未向外部平台发布任务。

本文收敛当前讨论与源码研究。六项产品选择已经由用户确认，其余工程选择由本规格明确限定，以便后续实施；研究文档中的其他候选能力不自动成为本期需求。

## Problem Statement

用户希望将工作分给多个子代理，在它们工作期间继续与主代理协作，随时补充要求或停止某一个，并在工作结束或应用重启后查看成果、继续原有调查。

现有内置子代理以一次阻塞工具调用承载整个任务。同批子任务虽然可以并行，主代理仍需等整批返回；途中通信、独立停止、完整历史保留和跨重启继续没有形成统一的行为契约。任务结果与启动工具卡绑定，难以承载独立生命周期。空回答后从头重试可能重复已执行操作，等待并发名额又会消耗执行超时。

本次重构需要形成可观察、可控制、可继续的子代理协作，同时保留现有模型执行、工具、技能与上下文压缩能力。

## Solution

主代理派工后获得子代理标识并继续工作；每个子代理独立执行、回报结果。用户可在当前对话的子代理面板查看任务、发送补充信息、停止或继续指定子代理。一次子任务完成后释放执行资源，保留子代理身份与历史；新工作可以继续原子代理，也可以创建新的子代理。

| 决定 | 已确认的产品行为 |
|---|---|
| D1：保留与继续 | 完成后保留历史，可继续同一子代理，也可新建；完成不等于删除。 |
| D2：管理入口 | 主代理和用户都能管理子代理；用户无需总是通过主代理转达。 |
| D3：主代理收尾 | 主代理默认收齐本任务依赖的子任务结果后再结束本轮，期间仍可工作和接收用户消息。 |
| D4：途中消息 | 新消息默认补充要求，在下一个可接收边界处理；明确要求停止或改方向才中断，不自动撤销已执行操作。 |
| D5：停止范围 | 主对话停止整个当前协作；子代理卡片停止对应子代理分支，其余工作继续。 |
| D6：重启恢复 | 跨重启保存历史、结果与已受理的补充消息；未完成工作标记已中断，用户或主代理明确继续后才运行，不自动重跑。 |

“收齐所需结果”包括完成结果、失败报告或中断原因；不能因某个子任务失败而无限等待成功答案。主代理应说明失败或缺失对结论的影响。用户停止整个协作时，停止优先于继续等待。

## User Stories

1. 作为用户，我希望主代理派出子代理后仍可继续工作，以便并行处理不依赖子结果的部分。
2. 作为主代理，我希望启动子代理后立即获得可查询的标识，以便后续发送信息和读取状态。
3. 作为主代理，我希望一次派出多个独立子任务，以便并行调查不同问题。
4. 作为主代理，我希望先收到已经完成的子结果，以便不必等最慢的子代理才处理其他结果。
5. 作为用户，我希望每个子代理有清晰的名称、任务和状态，以便知道谁在做什么。
6. 作为用户，我希望能创建新的子代理，也能继续已完成的子代理，以便按任务需要选择上下文。
7. 作为主代理，我希望继续子代理时保留此前消息和工具结果，以便避免重复调查。
8. 作为用户，我希望子代理完成后不继续占用运行名额，以便发起更多工作。
9. 作为用户，我希望在子代理面板直接发送补充要求，以便及时纠正方向。
10. 作为主代理，我希望向运行中的子代理补充新发现，以便它在现有工作基础上调整。
11. 作为用户，我希望区分消息已受理与已被子代理接收处理，以便知道要求是否仍在等待。
12. 作为用户，我希望发送补充信息时保留已做工作，以便不因普通插话反复重启任务。
13. 作为主代理，我希望向空闲子代理留言而不立即运行模型，以便先积累材料再交代任务。
14. 作为用户，我希望明确点击继续后才启动空闲或中断的子代理，以便掌握执行时机。
15. 作为主代理，我希望在空闲子代理收到后续任务时启动新的执行轮次，以便继续利用它的历史。
16. 作为用户，我希望任务恰好结束时发出的消息仍然保留，以便不会因时序巧合丢失要求。
17. 作为用户，我希望停止某个子代理而不影响其他子代理，以便缩小或纠正工作范围。
18. 作为用户，我希望主对话停止按钮停止整个当前协作，以便点停止后不再悄悄派工。
19. 作为用户，我希望知道停止仍在处理中还是已确认结束，以便不把停止请求误当作已经停完。
20. 作为用户，我希望停止保留已完成成果，以便后续查看和决定是否继续。
21. 作为用户，我希望过期的停止操作不会停止新启动的一轮，以便避免界面延迟导致误操作。
22. 作为主代理，我希望等待消息时能被用户的新输入唤醒，以便持续响应用户。
23. 作为主代理，我希望等待超时不终止子代理，以便长任务可以继续执行。
24. 作为用户，我希望主代理的最终答复说明所依赖子任务的结果和失败，以便理解结论的依据与缺口。
25. 作为用户，我希望切换对话或重新打开面板后看到完整状态，以便不依赖始终开着某张卡片。
26. 作为用户，我希望退出并重启应用后仍能查看子代理历史和结果，以便接着处理长期工作。
27. 作为用户，我希望重启后已受理但未消费的消息仍然可见，以便知道哪些要求还未处理。
28. 作为用户，我希望重启不会自动重新执行命令或写入，以便避免重复操作。
29. 作为主代理，我希望中断后的继续能知道哪些工具已完成、哪些结果未知，以便作出正确的后续判断。
30. 作为用户，我希望达到并发限制时收到清楚的反馈，以便决定等待已有任务还是减少派工。
31. 作为用户，我希望不同对话中的同名子代理互不干扰，以便名称相同也不会错误转发消息。
32. 作为用户，我希望区分启动成功、任务完成和执行失败，以便不会把回执当成果。
33. 作为用户，我希望卡片展示简洁摘要、详情保留完整结果，以便兼顾浏览与核查。
34. 作为用户，我希望子代理按父对话的授权与工作目录执行，以便现有项目行为保持一致。
35. 作为主代理，我希望模型空回答的恢复保留已执行工具历史，以便不从头重复具有副作用的工作。
36. 作为用户，我希望旧对话中的子代理卡片仍能打开，以便升级后原有记录继续可读。

## Implementation Decisions

### 1. 一个控制接口，复用现有执行循环

以子代理管理模块作为唯一控制入口。模型工具和桌面命令都是该接口的调用方，不能分别维护另一份任务状态。该模块负责身份、执行句柄、消息受理、停止、结果记录和状态查询；内部通过子代理宿主调用现有 Agent 执行循环。

复用现有 AgentHost 与 ToolExecutor 接缝、模型请求流程、工具权限、角色与技能加载、上下文压缩、用量统计。新增的主要外部接缝是子代理控制接口；存储、事件发布与执行依赖位于它的内部，不为每个操作新建一套执行框架。

运行句柄由管理模块持有。调用方不等待结果、工具回执发送失败或页面卸载，都不能意外丢弃执行控制权。任务结束、准备失败、取消、异常退出都必须完成状态整理和资源释放。

### 2. 区分身份、执行轮次与消息

| 对象 | 所有权与必要信息 |
|---|---|
| 子代理 | 稳定标识、所属父对话、父子关系、名称、角色及配置快照、历史引用、最近执行。名称只在所属协作中解析。 |
| 子任务执行 | 独立执行标识、目标子代理、发起者、输入与所依赖父轮、状态、结束原因、完整结果及用量。 |
| 协作 | 当前主任务及其受理的子任务集合、停止状态、待处理结果；不依赖某次启动工具调用存活。 |
| 消息 | 稳定消息标识、发件者、收件者、类别、受理顺序、预期执行及消费执行、受理与消费状态。 |
| 工具执行记录 | 工具调用身份、输入、执行前记录、结果或中断/未知状态，属于具体子任务执行。 |
| 完成投递记录 | 子任务执行标识、权威结束状态、结果引用、父方接收状态，支持重复投递去重。 |

一个子代理同时最多有一个执行循环。完成、失败和中断都终结当前执行，但保留子代理身份。继续空闲子代理创建新的执行标识，沿用历史；旧事件不能覆盖新执行的状态。

### 3. 控制操作契约

下表规定行为，具体工具和命令名称可沿用项目命名方式；不同入口必须遵循相同规则。

| 操作 | 契约 |
|---|---|
| 启动子代理 | 验证上下文、配置及容量，持久受理身份和初始任务后返回标识；不等待最终回答。受理键支持调用方重试去重。准备失败必须可观察且释放名额。 |
| 发送补充消息 | 持久受理后返回消息标识与状态。运行中在下一个允许边界消费；空闲或已中断时只留言，不隐式开始执行。 |
| 交代后续任务／继续子代理 | 空闲时显式启动新执行并读取未消费消息；运行中作为当前执行的补充要求处理，回执明确指向当前执行，不另起第二个循环。 |
| 中断指定分支 | 携带目标和预期执行，停止该分支的当前工作并封住该次执行的新增派工；过期目标返回明确冲突。 |
| 停止当前协作 | 封住当前协作的新派工与自动继续，再停止主代理及所有已受理子执行；不影响其他独立对话。 |
| 等待活动 | 从给定事件位置等待新消息或状态变化，返回活动摘要或超时；不吞掉消息，不取消子执行。 |
| 查询列表／详情 | 返回权威状态、当前执行、最近结果、消息状态及可用操作，按所属对话限制范围。 |

用户直接停止的分支不能被主代理当作临时错误立即自动重启。新的用户继续指示，或用户允许后由主代理明确继续，才能解除该分支的用户停止状态。

### 4. 中途消息与冲突时序

普通消息在当前模型请求或工具执行结束后的下一次模型输入构建前消费。首版不强行打断流式请求来注入消息；长工具仍可通过独立停止操作取消。

同一子代理的消息按持久受理顺序消费，并保留发件者与消息类别。用户补充要求和主代理派工不能伪装成彼此的消息来源；用户明确纠正优先于与之冲突的代理指令。界面展示投递状态，不宣称模型一定已经理解或完成要求。

受理表示消息已可靠保存；消费表示消息已进入该执行的持久上下文，不表示业务要求已完成。重复投递相同消息标识不会再次追加上下文。消费记录与上下文追加应保持一致，不能先删除信箱再尝试保存历史。

在执行完成与消息到达竞争时，通过同一受理/收尾协调判定：收尾前已受理的运行中补充消息进入当前执行；收尾后受理的普通消息保留为空闲留言，并向调用方明确回执。后续任务若落在收尾之后，则按显式继续启动新执行。不得出现“显示已受理却无记录、无消费去向”的状态。

消息无法保存、容量不足或目标不存在时明确拒绝，不显示发送成功。已受理但因停止、退出而未消费的消息保留，在明确继续时读取；用户可查看其仍未消费的状态。

### 5. 结果收集与主代理收尾

启动操作成功只表示受理成功。任务完成依据子执行的权威终态，不能依据工具回执、等待工具结束或某次 UI 活动判断。

子结果按完成顺序提供给父方，各子执行互不等待。主代理可边处理已有结果边工作；没有可推进工作时，通过事件等待让出执行，不循环调用模型询问“完成了吗”。默认等待只监听所属协作的事件与用户输入。

父轮保存自己依赖的子执行标识。对尚未得到终态的依赖，正常收尾应进入可唤醒等待；得到全部终态后再形成汇总。不能将旧执行的结果误当作同一子代理新执行的答案。失败和中断必须如实进入汇总，不得伪装成成功。

父用户停止、应用退出以及主执行不可恢复的错误可以提前终结父轮。主执行发生不可恢复错误时，停止本次协作中仍活跃的子执行并记录原因；已经持久完成的子结果仍保留。父轮封口或不存在活跃模型执行，不得妨碍结果落盘、查询与后续读取。

子结果到达空闲父方时只记录并提供可见状态，不自动开启新的父模型调用。它可以唤醒尚在等待中的父执行；这是继续同一次工作，不是自动新建父轮。

### 6. 中断、退出与恢复

| 情况 | 规定行为 |
|---|---|
| 请求停止 | 先标为正在停止，发送取消信号；确认循环与受管理工具清理结束后，进入已中断。 |
| 执行与停止同时结束 | 以实际已提交的权威终态为准；已经完成的成果不被迟到停止请求改写为丢失。 |
| 工具无法确认终止 | 保留尚未确认的执行状态及原因，不能提前宣称已停完；已知仍运行的资源保留控制入口。 |
| 切换对话或关闭面板 | 仅取消该视图订阅，应用仍运行时不停止后台子执行。 |
| 正常退出应用 | 拒绝新增工作，停止并清理当前执行，保存历史与待处理消息；不留下由应用管理的孤立 worker。 |
| 崩溃、强制结束后启动 | 将未结束执行恢复为已中断，附“进程中断”原因；不自动调用模型、不重放工具。 |
| 明确继续 | 从持久历史启动新执行，读取仍待处理的信息，并告诉模型前次中断位置及结果未知的工具。 |

中断保留已经执行的文件修改；不提供自动撤销。已记录工具完成结果不重复执行。若崩溃发生在外部操作已生效但结果尚未落盘的间隙，应显示结果未知并要求后续先核查外部状态，不能从“没有成功记录”推断“没有执行”。

首版的继续是保留上下文后的新执行，不是冻结和恢复网络请求、Rust future 或 shell 进程现场。界面使用“停止／继续”，不承诺冻结现场式“暂停”。

### 7. 持久记录与事件协议

沿用项目现有文件式持久化与仓库写入约定，不为此功能引入新的数据库或外部消息服务。子代理记录属于父对话，具有版本化结构，支持旧记录缺少字段时降级读取。

启动和消息的成功受理回执必须发生在可靠保存之后。工具副作用开始前先保存执行意图，工具完成后保存结果；其目的在于发现中断窗口，不承诺任意外部副作用恰好执行一次。

子任务终态、结果引用和待投递信息必须能通过一次原子提交或可恢复的写入过程保持一致。父方接收按子执行标识去重，已消费完成结果不能重复进入模型历史。投递失败可以重试，结果本身不依赖投递成功才存在。

界面使用独立子执行事件与快照，包含所属对话、子代理、执行标识及单调事件序号；不将异步事件强塞入已经终态的父轮。重连时使用快照和序号补齐；事件回放缓冲不足时重新取快照，不能仅靠直播旁路恢复。

运行时只保留必要的活跃对象与有界查询缓存，历史和完整结果按需读取。旧的进程内记录上限不能用于静默删除可继续的历史。随父对话删除处理从属记录；删除活跃父对话前必须先完成相应停止流程。首版不增加独立子历史清理产品功能。

### 8. 并发与超时

保留现有子代理并发设置的数值与可调范围：默认 12，范围 1—64。本期明确其含义为应用进程内同时活跃的内置子执行数，不含主代理；空闲、已完成或仅保存历史的子代理不占运行名额。

容量受理采用原子预留。首版容量满时明确返回资源不足，不在启动工具内部无限排队，也不创建用户看不到的等待任务。主代理可等待已有子任务结束后重新派工；相同受理键不会重复创建任务。调低上限不强杀已有任务，新任务等实际容量恢复后才可受理。

执行名额覆盖已受理、启动中、运行中及尚在清理的执行，统一释放。多个同时启动请求不能因为先检查后增加计数而超额运行。

启动回执期限只约束受理阶段；等待超时只约束等待；模型请求与工具各自保留合理超时。本期不保留覆盖整个子任务的固定 660 秒启动工具超时。子执行持续到完成、明确停止或执行错误；已有工具轮次等限制仍适用。

### 9. 上下文、角色与工作目录

首版新建子代理使用独立的新上下文：角色、已加载技能、完整任务描述和父代理显式提供的材料。不会默认复制整个父对话。继续同一子代理时加载自己的历史，并正确使用已产生的压缩历史，避免把压缩前历史重新拼回。

继承现有角色、模型选择和权限筛选行为，保存实际使用的配置。运行中补充消息不会隐式改变模型、角色或工具授权。继续时保留角色和模型选择，同时重新核对当前授权与凭据；已撤销授权不能因历史快照重新生效，不可用配置返回明确错误。

子代理仍使用父对话的工作目录和附加目录授权。独立消息上下文不代表文件隔离；派工应明确工作范围，主代理避免将同一文件交给多个子代理同时修改。首版不自动创建 worktree，不声称具备写冲突合并能力。

首版只开放主代理派工的一层子代理，不开放子代理继续派工或跨父对话控制。内部保留父子关系，停止使用分支语义，以便未来拓展而不改变用户理解。

### 10. UI 与旧行为兼容

当前对话提供子代理列表与详情，展示名称、任务、角色/模型、执行状态、进度、用量和结果。用户可查看完整历史、发送补充信息、停止对应分支，并在空闲或中断后继续工作。运行中提供补充信息入口，空闲时明确区分留言与继续。

输入卡显示受理、待消费、已消费或拒绝状态。停止按钮显示正在停止直至收到权威终态；失败时保留错误提示。用户操作、主代理指令、子任务汇报保留来源，避免将子代理文本显示为用户指令。

旧的启动工具卡继续可读；缺乏完整子历史的旧记录只提供查看，不能展示不可实现的继续操作。短摘要不能替代完整结果；历史中仍可查到启动回执和最终结果的分别来源。

内置子代理在后台任务表示中有独立任务类别和能力，不复用停止 shell 命令的路由。外部 CLI 代理保留其已有执行与控制路径，不能因为同样展示为子代理就宣称支持全部新能力。

迁移期如保留旧阻塞工具契约，应作为新控制入口上的启动加等待兼容适配；只维护同一套子代理执行实现。新增异步工具成为新调用路径，旧历史无需重写。

## Testing Decisions

### 测试接缝

主验收接缝是用户与模型共享的子代理控制接口。测试跨越它运行真实调度、状态变迁和现有 Agent 循环，使用可控模型响应与已有 ToolExecutor 替身；时间、存储失败及事件投递在内部替换。真实文件式存储至少有重启读取与写入故障回归。

现有主循环 steering、follow-up、取消、子代理结果整理及并发屏障测试作为先例。新增测试必须覆盖生产控制逻辑，不能只用复制阻塞行为的 spawn shim 证明异步架构正确。UI 测试验证操作、回执和重连呈现，不只匹配标签文字。

### 验收矩阵

| 编号 | 可观察行为与通过条件 |
|---|---|
| A01 | 用屏障阻住子模型时启动已返回；父代理可以执行不依赖子结果的工作。 |
| A02 | 两个子任务中 A 先完成，父方收到 A，B 仍运行；不等待整批 future。 |
| A03 | 同一启动受理键重复提交只有一个子代理和一次初始任务，回执丢失后可查询。 |
| A04 | 同一子代理同时接到多个继续请求不会出现两个执行循环，回执对应正确执行。 |
| A05 | 运行中补充消息在约定边界进入模型输入一次，原执行工具成果仍在。 |
| A06 | 空闲普通留言不调用模型；明确继续读取旧历史和未消费留言。 |
| A07 | 消息与执行结束同时发生，消息被当前执行消费或明确保留为空闲留言，没有静默丢失。 |
| A08 | 消息保存失败返回拒绝；成功回执对应消息可在重启后读取。 |
| A09 | 检查 pending 状态与订阅之间到达的事件不会漏唤醒；重复等待不重复消费消息。 |
| A10 | wait 超时或用户新输入只结束等待，其他子执行继续。 |
| A11 | 停 A 不停 B；停止处理期间状态可见，确认清理完成后才显示已中断。 |
| A12 | 旧执行的停止请求不能停止同一子代理的新执行；已完成结果不被迟到停止覆盖。 |
| A13 | 主停止先封住派工，再取消所有已受理子执行；与同时到达的派工竞争时不漏掉新 worker。 |
| A14 | 用户停止分支后主代理不会自动重试；得到新的继续指示后可以重新运行。 |
| A15 | 工具未确认终止时不能显示已停完；退出清理不存在被丢弃句柄的受管理 worker。 |
| A16 | 子任务失败或中断后，父代理能说明缺失并结束；依赖仍运行时不会提前宣称任务完成。 |
| A17 | 父轮终态之后，子结果仍落盘可读；空闲父方不会被完成通知自动启动新模型调用。 |
| A18 | 终态重复投递与乱序事件不重复注入模型，不把已完成执行改回 running。 |
| A19 | 关闭面板、切换对话再打开后，以快照和事件位置恢复任务、消息及结果。 |
| A20 | 崩溃重启后未终态执行显示已中断，已受理未消费消息仍在，没有自动模型调用或工具重跑。 |
| A21 | 工具已完成后模型空回答，只重试模型步骤；已完成写入不重复执行。 |
| A22 | 外部工具可能已生效但完成记录未写入时，恢复显示结果未知，不自动重放该操作。 |
| A23 | 原子容量预留防并发超额；受理失败、panic、停止与清理均释放名额；空闲历史不占名额。 |
| A24 | 容量满明确拒绝且无幽灵排队任务；调低上限不强停旧任务；新启动不受旧的整任务 660 秒限制。 |
| A25 | 不同父对话同名子代理不能互相收信或被误停；缺失或越界目标返回明确错误。 |
| A26 | 子结果卡片可截短摘要，详情保留全文；压缩后的继续没有拼回旧上下文或重复计用量。 |
| A27 | 继续子代理时撤销的授权仍被撤销，不可用模型或凭据有明确错误；新建仍为独立上下文。 |
| A28 | 用户和主代理控制同一对象时经过同一接口；UI 不将内置子代理停止路由至 shell。 |
| A29 | 旧历史卡片保持可读，无完整历史时不提供继续；外部 CLI 行为不因内置重构被替换。 |
| A30 | 存储和事件投递在终态前后故障时，恢复得到一致终态与可重投递结果；不存在只有 UI 完成而结果未保存。 |

测试报告必须区分确定性单元/集成验证、存储恢复验证和实际 provider 端到端验证。已有 32 项子代理测试通过是旧实现的基线，不是本规格的验收结果。

## Out of Scope

- 发布 issue、拆任务、开始实现、部署或迁移现有用户数据。
- 改写外部 CLI 代理自身的 SubAgent 调度，或统一所有 CLI 的完整控制能力。
- 默认复制完整父历史、最近若干轮 fork，以及跨模型 fork 优化。
- 子代理再次派工、多层协作、跨父对话共享子代理。
- 自动 worktree、并行文件写入隔离或自动合并冲突。
- 冻结并恢复正在执行的请求、进程或未结束工具；承诺任意副作用恰好执行一次。
- 重启后自动恢复运行、空闲父代理被子结果自动开启新轮，以及主轮结束后的独立后台执行模式。
- 新的资源计费体系、复杂优先级队列、LRU 调优与自适应调度；首版采用明确容量受理和按需历史读取。
- 动态编辑运行中模型/角色/授权、子代理单独审批产品流程及独立历史清理界面。

## Further Notes

本期完成的判定是上述用户行为与验收成立，而不是“后台启动成功”或“工具名与 Codex 一致”。历史保留、恢复和可靠投递属于本期基础能力，不能以先做异步为由留成不可兑现的按钮。

保留新建优先的工作方式，同时支持同身份继续。普通补充、明确继续和停止应在产品文案与后端事件中保持一致。任何改变已确认六项行为的实施方案，应先更新决定记录与本规格。

本地规格是当前重构范围的依据；研究报告保留源码事实和更广泛候选方案，已确认 ADR 记录产品取舍。本文没有逐项继承 Codex 的实现细节，也没有宣称其开源默认配置与本规格相同。
