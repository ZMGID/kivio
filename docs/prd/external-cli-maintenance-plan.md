# 外部 CLI 适配维护任务

记录日期：2026-11-06，更新于 2026-11-07。第 1 至 6 项已完成代码实现和下述自动化验证，提交后的整体审查见[维护变更审查记录](../research/external-cli-maintenance-review-2026-11-07.md)。

第二轮审查修复了首次补历史的安全重连、自定义 HOME 文件指纹、自动化及压缩的失败终态传播、诊断对话归属。新增 11 项针对性回归通过，Windows Rust 全量 lib 测试 3232 项通过、56 项按原配置跳过。完整结果、存量格式差异与未验证风险见审查记录的「第二轮审查修复」。

目标是让各 CLI 的适配、能力差异、运行生命周期和账号配置有明确归属。问题依据见[审计报告](../research/external-cli-maintenance-audit-2026-11-06.md)，实现遵守[统一工程规范](../engineering-standards.md)。

- [x] **1. 独立 Provider 与能力建模。** 基于现有可用实现，给每个 CLI 明确的 Provider 模块归属，集中定义、专属启动规则和能力声明，共享 ACP 与传输代码。能力区分原生支持、降级支持和不可用，UI 与后端使用同一份契约。T3 作为设计参考，保留 Kivio 现有协议 actor、会话和进程机制，不另建运行框架。完成后，能力和入口判断不再散落为布尔字段及前端 CLI 名单。
- [x] **2. 运行身份与进程生命周期。** 区分运行实例、会话绑定和单次运行，统一 binary、执行环境、配置与凭据代次。管理启动、停止、重连、删除和退出，修复 generation 清理与旧实例干扰。取消在提示词提交前检查，已知启动身份变化会拒绝旧进程复用，Windows 受管后代通过真实进程测试验收；其余平台限制见实现记录。
- [x] **3. 协议边界与交互归属。** 统一帧校验、请求关联、审批问答、后台事件和终态处理。宿主交互身份唯一，原生 ID 保留在对应连接内。按交付阶段决定重试。完成后，同名 ID 不串对话，迟到结果不污染新运行，断线不盲目重发已执行的工具轮。
- [x] **4. 导入、续聊、分支与回退。** 统一绑定、原工作目录校验、导入防重及失败恢复。分支使用独立原生会话或一次文本补历史，回退状态关联已提交版本。完成后，可见历史与模型上下文一致，失败不留下半成品，源会话仍可使用。
- [x] **5. 安装更新与账号隔离。** 固定安装来源、执行环境和目标版本，检查运行占用并验证实际 binary。保留 CLI 自身配置的共享模式，明确私有账号边界。由后端设置提交负责凭据清理。完成后，不更新错安装，失败保留有效配置，账号展示与实际执行一致。
- [x] **6. 协议回放与诊断。** 保存脱敏的真实协议记录，接入现有测试与 CI。覆盖多轮、恢复、停止、引导、审批、断线、分支、回退及后台迟到事件。日志有大小限制、脱敏和请求归属。完成后，关键故障可离线重放，CLI 升级有兼容性检查。

每项都随实现补回归测试，通过验收后再勾选并提交一次 Git commit，同时删除被替换的旧路径。第 6 项是长期回放体系，不意味着前五项可以推迟测试。Windows 与 WSL 的进程和环境行为分别验收。

保留现有 ADR 对导入后原 CLI、原工作目录和回退补历史的约束。暂不扩展远程执行、文件 checkpoint 或跨 provider 导入切换。

第 1 项实现记录：十个 CLI 各有 `src-tauri/src/external_agents/providers/<cli>.rs`，注册仍使用原来的 `RuntimeAgentDef`。统一能力覆盖运行中引导、原生追加、图片输入、回退、分支、导入历史和账号查询，经现有协议生成工具提供给前端。账号入口、消息队列和导入提示读取后端声明，旧缓存返回时补齐当前能力。Codex 的服务等级、启动指纹和会话丢失识别，以及 dsh 的启动指纹回到所属 Provider。

能力描述的是 Kivio 当前接入的行为，实际执行仍服从原有协议协商和响应。第 4 项补齐普通分支的独立原生上下文和首次补历史；安装更新和账号隔离仍按第 5 项推进。

第 1 项验证：861 项外部 CLI Rust 测试、3 项交互命令测试、146 项前端测试通过；协议生成与一致性、TypeScript、修改文件的 ESLint、新 Provider 模块格式和架构检查通过。45 项真实 CLI 测试按现有配置跳过，未执行真实 CLI 的桌面联调。

第 2 项实现记录：参考 T3 的启动归属、进程范围和迟到事件隔离，继续使用现有 `AgentChild`、协议 actor 和 `LiveSessionRegistry`。Windows 在启动时纳入 Job，统一覆盖会话、探测和 ACP terminal；主进程退出仍清理后代。会话注册表负责启动占位、精确实例回收和有界关闭，旧实例不能移除替代实例或重新发布已删除的绑定。删除失败释放“删除中”标记，未完成的进程清理继续阻止复用。

单次运行在共同入口持有 generation，普通发送、自动化及上下文命令共用清理。停止在入队和协议发出提示词前校验；协议收尾超时后终止旧连接，但继续保存已收集的回答。审批等待随运行释放，ACP terminal 的 kill/release 等待退出和尾部输出。启动身份覆盖本机 binary 元数据、环境、设置代次及已知配置/凭据文件；设置提交失败恢复镜像，普通读取不再改变运行身份。

第 2 项验证：877 项外部 CLI 测试、226 项聊天运行态/存储/设置/自动化/语音测试通过，架构检查及差异空白检查通过。Windows 真实进程回归覆盖主进程先退出、显式取消、资源释放、宿主崩溃及 ACP terminal 尾部输出，并确认不影响独立进程。46 项标记跳过的测试包括 45 项真实 CLI 测试及 1 项由父测试调用的进程夹具。

验收限制：未执行真实 CLI 的桌面联调。当前机器 WSL 不可用，未验证 Linux/macOS；Windows Job 不证明 WSL 内 Linux 后代已退出，WSL binary 内容及发行版内凭据变化尚不能完整识别。POSIX 仍使用既有进程组，不能覆盖脱离组的后代或宿主被 SIGKILL 的情况。生产关闭等待 actor 和主进程清理，未查询 Windows Job 全部成员归零；测试通过持有实际后代进程句柄确认退出。

第 3 项实现记录：参考同一 T3 快照的严格 ACP 读取、请求关联和交互身份分离，继续修改现有协议 actor、运行入口和 Chat 交互状态。ACP、Codex、dsh 区分请求、通知与响应，保留原生 ID 类型并匹配对应请求；Claude、Pi 的活动读取拒绝坏 JSON 和缺少必需字段的帧。未知的合法可选通知仍可忽略，Codex 的全局配置警告和配额通知继续显示。ACP 取消使用无 ID 通知，导入更新按原生会话过滤；Codex 的开始信号或匹配响应确定原生轮次，旧轮终态不能结束新轮。

每次审批与同步问答使用新的宿主交互 ID，工具 ID 继续关联卡片，原生请求 ID 留在 actor 内回包。主窗、弹窗、快照和撤回共用该身份，旧点击不能认领后续请求。已回答内容按运行隔离并随运行清理。后台任务按对话、实际进程和原生任务 ID 归属，停止只向原进程发送；dsh 后台进度也按进程匹配工具卡，CLI 后续进度可以纠正未成功的乐观停止。

各 actor 在首次写入提示词或压缩命令前标记可能已发送。共同运行入口只对明确未发送的失败自动重试，actor 收据丢失按不确定投递处理，避免断线后自动重复执行。未新增运行框架或依赖。按领域建模分开工具、交互和进程身份，按边界校验保留各协议差异，行为测试经过现有读取和派发路径。

第 3 项验证：892 项外部 CLI 测试、68 项聊天交互/协议/运行清理/桌宠测试通过，139 项前端测试通过；协议生成与一致性、TypeScript、修改文件的 ESLint、架构及差异空白检查通过。新增回归覆盖真实管道对端、坏帧、反向请求与响应同 ID、旧轮通知、审批 ID 复用、可能已发送后的失败及后台任务跨进程归属。46 项标记跳过的测试仍按原配置跳过。

第 3 项验收限制：实机仅核对本机 Codex 0.166.0 的生成 schema，以及 Grok/OpenCode 的无提示词 ACP 握手和 OpenCode 列表/加载响应。未执行真实模型聊天或桌面完整联调，未验证其他 CLI 版本、Linux/macOS 和 WSL；模型与命令探测保留既有容错策略。长期真实 transcript 回放体系仍归第 6 项。

第 4 项实现记录：参考 T3 快照 `6577c6b6185167c0e502fa01f9e8e8f2dee6ff25` 的 `ThreadForkService`、`ContextHandoffDelivery` 和 `CheckpointRollbackService`，继续使用现有 Conversation、仓库 CAS、协议 actor、原生绑定及提示词组合。原来分开写入的回退 marker 改为随截断历史原子提交的待处理状态，关联提交版本、历史边界、原生会话和本次运行。只有匹配且成功的回答落盘才能结清状态；不确定交付后的下一次用户操作建立新原生上下文，并补入当时的可见历史。取消时仍保存已经收集的回答。

普通分支使用独立会话并在首次发送时补历史，保留源会话；分支后的重新生成也更新待补历史边界，当前提问只发送一次。旧 marker 保守迁移为文本补历史，删除旧 marker 写入路径。原工作目录由现有绑定和导入记录负责校验，普通发送与自动化共用。绑定后的空会话也锁定运行时，后端仓库、主窗、弹窗和发送准备共用该规则。

导入按 CLI 与原生会话加锁防重，先恢复已提交结果，再读取原生来源。导入记录和绑定先准备，正文提交后才发布；正文未提交的失败清理暂存文件，正文已提交但索引写入失败时保留完整数据并在重试中恢复。再次导入不依赖原生来源仍然存在。图片写入失败不再静默丢图。Kimi 按当前上游 ACP 重放实现更新能力，拒绝没有可显示重放历史的响应；版本证据和旧实现差异见 [ADR-0003](../adr/0003-acp-agents-import-via-protocol.md)。未新增运行框架或依赖。

第 4 项验证：Windows Rust 全量 lib 测试 3189 项通过、56 项按原配置跳过，其中外部 CLI 专项为 897 项通过、46 项跳过；聊天前端 2150 项通过。首次全量 Rust 测试的 9 项失败均因 `python` 命中 Windows Store 占位程序，使用本机 Python 3.12 的进程级 PATH 复跑全部通过，未修改系统配置。真实临时文件与无窗口 Tauri 夹具覆盖导入写入失败、索引失败后恢复、并发防重、来源不可用时重复导入、分支文件清理、回退版本冲突、取消后续聊、迟到回执、旧 marker 恢复及分支重新生成；通过现有 RunTurn 入口检查实际派发提示词，验证补历史只执行一次。空绑定会话回归已在原实现复现失败。协议一致性、TypeScript、修改文件 ESLint、架构及差异空白检查通过。

第 4 项验收限制：未执行真实模型聊天、桌面完整联调及真实 CLI 的原生回退连接流程。当前机器 WSL 返回 `Wsl/CallMsi/Install/REGDB_E_CLASSNOTREG`，仅验证路径转换规则；未执行 Linux/macOS 测试。本机未安装 Kimi，其能力依据已固定版本的上游源码，旧版不重放历史时会明确拒绝导入。跨模型家族审查因可用模型仅属 GPT 家族而跳过，已完成独立同家族审查。

第 5 项实现记录：参考同一 T3 快照的 [maintenanceResolver](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/packages/provider-core/src/server/maintenanceResolver.ts)、[ClaudeHome](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/provider/Drivers/ClaudeHome.ts) 和 [CodexHomeLayout](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/provider/Drivers/CodexHomeLayout.ts)，继续修改现有 installer、AgentChild、会话注册表和设置提交入口。安装预览由后端保存短期有效、只能消费一次的计划，固定实际 binary、执行环境、已证明的 npm 来源和 prefix，以及精确版本；页面提交计划 ID，日志也按计划关联。执行前拒绝失效计划，完成后只校验计划中的 binary 和版本。无法证明目标的原生安装、其他包管理器及 WSL 安装显示原因并转为手动维护，删除原先不绑定目标的安装更新路径。

进程启动、探测与维护共用现有生命周期中的资源占用记录，覆盖 CLI、binary、npm prefix 和配置路径。设置提交在文件写入前检查占用，异步入口退役闲置 actor；运行中、启动中或探测中的冲突返回可重试失败。供应商删除由后端设置提交统一处理，页面只修改草稿，删除旧的前端凭据清理 IPC。cc-switch 列表只向前端返回元数据，确认选中后才返回对应凭据。

凭据物化与清理复用 provider_profile，提交前保存受影响文件的原字节、权限及原本不存在的状态，设置文档最后写入。失败恢复这些文件，回滚失败保留占用并在下次保存时重试恢复。仍支持「CLI 自身配置」共享模式；Claude 的私有 settings 只隔离路由配置，不承诺完整 HOME 或登录态隔离；Codex 使用私有凭据并继续共享原生 sessions。选择 Codex 私有供应商时拒绝冲突的手填 `CODEX_HOME`，原生共享模式仍可使用自选目录。账号探测与执行使用相同 Claude overlay，设置变更会刷新账号展示，旧请求不能覆盖新结果。未新增运行框架或依赖。

第 5 项验收限制：自动维护目前只接受能够证明归属的 npm 全局安装；Windows 只识别已验证的 npm shim 格式，其他包装器保守转为手动维护。dsh 缺少 pnpm 时提示手动安装，不再另外安装未绑定目标的全局包管理器。旧版原生配置备份未记录原目录，无法证明归属时拒绝写入并保留备份，按错误指引恢复后再保存，不猜测当前环境变量指向的目录。原生配置目录必须为绝对路径；已有相对路径需要先确认并修复原目录，不能自动推断旧工作目录。占用互斥覆盖 Kivio 管理的进程和文件写入入口，不覆盖外部终端同时运行的 CLI。配置文件回滚在当前进程内执行，不保证宿主崩溃时跨文件原子提交，也不承诺 npm 安装失败后回退包版本。未修改本机真实 CLI 安装或账号来验证，也未执行桌面完整联调、WSL、Linux/macOS 实机测试。跨模型家族审查因可用模型均属 GPT 家族而跳过。

安装预览在解析 binary 及查询 registry 的等待前后检查配置代次；本次未演练挂起 registry 响应的完整 IPC 竞态。Claude 账号查询复用执行参数并检查结果身份，本次未新增完整 Claude 账号 wire protocol 演练。上述行为经过源码审查和共用边界回归，不作为真实服务端到端验收结果。

第 6 项实现记录：参考 T3 的原生诊断摘要与真实传输回放，继续使用 AgentChild、现有协议 actor 和回归测试入口。AgentChild 的管道包装统一观察六种协议的握手、活动轮和空闲流量；语音 Codex 与账号探测的同类管道调用方一并迁移。没有新增运行框架或依赖。请求调试开关控制 `<app_data>/usage/native-protocol/current.jsonl` 和 `previous.jsonl`，已连接的会话也服从开关变更。
