# SDK 分支审查记录

本次工作按用户要求审查整个 SDK 分支，修复确认的问题，验证后提交并推送。审查基线为 `7a7e10b81b37b35758dff840a32d2e07138bdee6`，原分支头为 `906c0db9895b9483a5b878d93e38682f49701add`，共六个 SDK 提交、156 个变更路径。

## 审查范围

独立审查分别覆盖 SDK 循环和生命周期、模型协议和重放、应用宿主与权限，以及注释和公开承诺。协调者复核报告、比较原实现、补充真实 HTTP 回归，并检查依赖、打包和 CI 配置。审查模型均属于 GPT 系列，没有跨模型家族复核。

SDK 继续负责循环、规范历史和事件。桌面宿主继续负责权限、持久化、会话代际、子代理清理及应用重试。OpenAI 编解码由 SDK 共享，其余供应商通过应用适配器接入。本次未发现需要迁移这些归属的证据。

## 已确认的问题

1. 未注册工具时，循环直接进入一次纯文本回答，跳过插话、后续消息及会话边界。预先成功入队的输入没有被消费。新增公开消费者用例通过真实 HTTP 复现。
2. 供应商拒绝工具后，原规划消息已结束，纯文本降级没有重新打开消息范围。新增用例观察到 `Content` 出现在消息范围之外。
3. 继续回答期间取消，原状态汇总会把已有推理再次重建为一条 assistant 历史。修复后的独立复查又发现，第二次纯文本请求在输出文字前取消会丢失之前的结果，部分输出的重放也会混入前一次推理。回归分别复现了重复历史和 `Err("cancelled")`。最终实现区分已有状态与当前部分输出，保留空输出、只有文字、只有推理的取消结果。显示用的汇总推理不再成为当前回答的重放内容。协调者另以公开接口复现了结束策略请求取消后仍返回 `Completed` 的问题，补充检查后，有工具与无工具两种情况都返回 `Cancelled` 并保留回答。
4. 文档把一次 `client.send()` 写成一次 HTTP 尝试。宿主传入的 reqwest client 仍可能自行重试或重定向。已修正文档和 rustdoc，明确 SDK 不增加重试循环，传输策略由 client 决定。此前决策记录和静态审查报告中的“一次 HTTP 尝试”不应作为传输保证。
5. 分支改动涉及的 41 个 Rust 文件未通过 rustfmt。已按文件格式化。逐一把 HEAD 源码在临时目录格式化后比较，除两处注释清理和一处测试局部变量改名外，结果一致。

## 修复选择

对比了统一外层循环和保留两种请求机制的方案。本次选择后者，在原循环负责人中共享输入准入和回答后的继续判断，保留规划与纯文本的请求、重试和恢复行为。成功回答的历史和分段只记录一次，规范重放不从展示文本重建。

保留桌面最终检查点的既有顺序。相关测试要求尾部宿主输入写入生成历史、位于最终回答之前，并且不额外发起模型请求。`AlreadyPersisted` 输入仍只进入工作历史。

`Fix Root Causes` 决定把两条路径缺失的边界规则统一处理。`Model the Domain` 决定使用私有回答类型表示待结束或继续的回答。`Laziness Protocol` 决定保留已有请求机制和公开接口。`Test Behavior, Not Implementation` 与 `Prove It Works` 决定通过公开 SDK、实际 HTTP 请求及最终历史验证缺陷，而非只验证内部函数调用。
