# 上下文压缩改造记录

日期：2026-09-27。参照用户提供的 ZCode 本地源码，主要对应 `compact/policy.ts`、`compact/rounds.ts`、`runtime/methods/compact-active.ts`、`runtime/helpers/compact-preservation.ts` 与 `compact-post-reminders.ts`。本文记录实现，不增加工程规范。

## 原路径 → 新路径

原先发送前、循环内、回复完成后分别触发压缩；历史按固定 token 尾部切分，摘要请求使用文本序列化。现在自动策略集中在 `src-tauri/src/chat/agent/compaction.rs`，每次模型请求前检查预算，手动入口也调用同一个结构化历史摘要引擎。

- 预算采用模型窗口减去 `min(输出预算, 21000)`，再减 13000 安全余量；实际 provider usage 优先，无有效锚点才估算。
- assistant 消息开始一个消息组，连同工具结果及后续用户输入保留。自动压缩保留最近组，手动压缩汇总全部有效历史。
- 摘要请求保留消息角色与工具调用结构，并附带本轮的工具定义（超过 100 个时不附带，与 ZCode 一致），以便供应商接受工具调用历史、复用提示缓存；不附带时工具调用和结果转为文本；供应商拒绝工具定义时去掉工具重试一次，不计失败。手动压缩没有本轮工具，因此一律转为文本。提示词按九项交接信息组织，由本项目重新编写；摘要输出上限 20000，并受模型输出限制约束。
- 待摘要部分至少要有两组且含 assistant 回合，否则视为无需压缩，不发事件、不计失败。
- 自动摘要请求超窗（含空正文的 `length` 结束）时，把更多完整组移到保留区，不丢掉这些组；手动请求超窗允许最多三次移除最老组后重试，截断后若以 assistant 开头，先补一条截断标记。一般自动请求失败最多三次，每次从初始选区重来，认证错误直接失败。
- 自动压缩失败不结束本轮，请求照常发出；同一会话连续失败三次后暂停自动压缩（进程内按会话记录），成功一次或回退消息后清零，超窗触发的压缩不受暂停影响。压缩后连续三次在三批工具调用内重新超预算时，本轮以已收集的工具结果收尾。
- 真正的模型请求超窗可强制压缩一次并重试，绕过自动阈值。截断、空摘要、工具调用式摘要和取消不替换历史。
- 最近文件读取最多恢复五项；只取成功读取的文本文件结果（带行号范围头），单项超过 5000 估算 token 时仅留路径提示。工具输出微清理与 ZCode 默认行为一致，不默认开启；保留原有图片去重与体积保护。

## 保存与交互

`ConversationContextSummary.replay` 保存精确保留片段及覆盖终点。下一轮重建系统指令，再接摘要、保留片段和终点后的新消息。旧格式摘要仍可读取；原始聊天消息保持完整。修改覆盖范围内消息会让摘要失效，清空上下文也会使保留片段失效。

循环内摘要、保留片段和最终 assistant 回复在同次仓储写入中提交；刷新统计发生版本冲突时不覆盖新摘要。手动压缩使用现有发送预约、取消信号和版本检查；版本冲突时若被摘要的历史未变（仅统计刷新、改名或新增消息），重新提交，否则报错并保留原历史。手动摘要请求不带原始视频、按统一预算收敛图片，压缩模型已知不支持视觉时去掉图片。

主窗口手动压缩进入现有消息队列，重复请求去重，成功后使用返回的新会话快照继续队列；失败时报错并继续发送后续排队消息，停止时不自动发送后续消息。自动压缩进行中面板上的停止按钮显示为“停止生成”。主窗口和弹出窗口支持停止压缩；弹出窗口暂沿用直接手动请求入口。阈值由后端返回，前端不再写死百分比。

外部 CLI 的压缩仍由各自运行时处理。本次没有移植 ZCode 的整个会话存储、事件框架和供应商流式降级体系。

## 验证与边界

回归覆盖预算、消息组与工具配对、超限重选、手动全历史摘要、取消、截断拒绝、强制超限恢复、序列化后精确回放、旧摘要兼容、编辑失效、清空及队列交付。验证结果：后端聊天模块 994 项通过、1 项跳过；前端聊天模块 1694 项通过；协议解码 25 项通过。协议生成一致性、TypeScript、Lint、架构检查与差异空白检查均通过。

已补充真实模型桌面实测，结果与取消队列修复见[实测记录](context-compaction-live-test-2026-09-27.md)。实测采用合成历史，不能据此承诺所有任务的摘要质量或延迟。自动压缩检查点随本轮最终回复落盘；若进程在本轮完成前崩溃，恢复仍依赖原始历史与现有草稿日志，不声称与 ZCode 的中途持久化完全一致。
