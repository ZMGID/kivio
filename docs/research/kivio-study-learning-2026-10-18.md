# Kivio Study：论文与教材学习调研及架构建议

调研日期：2026-10-18。状态：调研与候选方案，未实现、未进行本轮原生 UI 验收。

## 结论与范围

用户明确：Study 面向论文、教材等材料的学习。推荐定位为**围绕原始材料，帮助用户读懂、留下自己的理解、检验是否学会的学习工作台**。文献管理是基础，不能让专业综述和投稿工具决定整个产品。

核心闭环：导入材料 → 找到章节或问题 → 阅读、解释与核验 → 保存带出处的理解 → 自测 → 回到薄弱处继续学习。跨论文比较是进阶能力，完整引用排版、团队系统综述和自动搜遍全网后写论文暂不优先。

本文不建立新的工程规范；实现遵守 ../engineering-standards.md、现有 ADR、PRODUCT.md 与共享组件规则。现有资料库三栏与阅读工作台两栏分别服务整理和学习，不相互取代。保留原文左、对话右的阅读骨架。

## 方法与证据边界

使用 Exa 进行 18 次检索，检索请求额度合计 93 条候选结果，其中一次无结果；这不是 93 个独立来源或受访者。覆盖五条线：文献管理、AI 阅读与证据、公开用户反馈、Kivio 代码、教材学习与检索练习。另批量展开六个关键网页；同一论文的 Science、PubMed 和 DOI 入口视作一项证据。

产品能力优先采用官方文档；用户需求采用 Zotero、MarginNote 原始论坛和开源插件记录。排除营销排行榜、无法核对原帖的 Reddit 镜像，以及厂商未经独立验证的效率和准确率宣传。论坛是自选样本，技术用户偏多；中文普通学生、手机用户和无障碍用户覆盖不足。下面的优先级是结合证据与 Kivio 定位作出的产品判断，不是市场占比或“所有人最想要”的统计排名。

旧帖子只证明曾有该需求，不能证明今日仍未解决。例如 Zotero 2026 年 7 月 beta 已加入更强的批注搜索，不能照搬 2024 年的缺失结论。[S9]

## 工具对照：分别学习什么

| 工具 | 本轮核验的能力 | 值得借鉴 | 对 Study 的取舍 |
|---|---|---|---|
| Zotero | 条目、批注转笔记、回原文、文字处理器引用、数据与附件分开同步 [S1–S3] | 资料可靠、引用与出处不丢、与写作衔接 | 保留轻量资料库，优先交换互通；暂不复制全部生态 |
| Mendeley | 文献管理、PDF 批注、跨 PDF Notebook、Word 引用 [S4] | 阅读笔记可以跨材料组织 | 不把账号云同步作为学习前置条件 |
| Paperpile | 导入、Google Docs/Word 引用、资料导出 [S5] | 少步骤收集与输出 | 以标准格式衔接写作；原生 Word 插件后置 |
| NotebookLM | 指定参与回答的来源，引用预览与来源定位 [S6] | 明确回答使用哪些材料 | 让来源范围可见，并跳到实际 PDF 原文；有引用不代表推理正确 |
| Elicit | 按列提取数据，单元格能查看支持引文，图表提取另有条件 [S7] | 多篇论文的结构化比较 | 后续做证据表；不把系统综述当首屏 |
| Readwise Reader | 高亮与笔记输出 Markdown、笔记工具连接、原始内容导出 [S8] | 学习产物容易带走 | 学习笔记导出应与阅读闭环同期考虑 |
| RemNote | PDF 内摘录、笔记、闪卡、分节学习与测验 [S14] | 从读材料走到检验理解 | 先做少量高质量自测，不一键生成几百张卡 |
| MarginNote | 主题学习集贯通材料、摘录整理与复习 [S15] | 多份材料围绕学习主题组织 | 先大纲与关联笔记；图谱作为可选视图 |
| LiquidText | 摘录与来源互连、跨材料整理、导出 [S16] | 笔记始终保留上下文 | 不急着建立复杂无限画布 |
| ResearchRabbit / SciSpace | 前者从种子论文发现关联研究；后者提供 PDF 问答与章节引用 [S17] | 前者适合扩展阅读，后者适合即时理解 | 发现文献属于后续入口，不能抢占读书主流程 |

EndNote 未完成独立文档核验，不据此作优劣排名。本轮也未进行竞品实机横评，不声称哪个产品实际最好用。

## 用户到底需要什么

| 实际任务 | 公开证据 | 产品回应 | 判断强度 |
|---|---|---|---|
| 我记得读过，但找不到那一段 | Zotero 用户请求直接检索批注、按标签找到具体片段；新版搜索讨论仍有人要求结果预览 [S9,S10] | 搜索结果直接显示命中段落、材料与页码，点击定位；搜笔记、批注与正文 | 多个原始讨论支持 |
| 做了很多笔记，写作或复习时仍需重新整理 | 用户请求笔记关系、提纲、顺畅的引用与键盘操作 [S11] | 保存自己的解释，按章节/主题组织；保留证据链接 | 明确但偏进阶用户 |
| AI 说得合理，我仍要检查出处 | NotebookLM 的来源引用设计、Elicit 单元格引文均支持核验流程 [S6,S7] | 段落/图表证据卡与原始页面定位；无依据时明确说明 | 能力设计有依据；需求普及度未量化 |
| 教材长，搜索和打开不能卡住 | Zotero 2025 年用户报告长 PDF 搜索等待；不是本轮性能实测 [S12] | 优先显示当前页、章节范围提问、后台渐进索引、可取消搜索 | 具体案例支持 |
| 英文材料读得慢 | Translate for Zotero 支持选词、批注与笔记翻译 [S13] | 段落解释/翻译与原文并存，术语可复查 | 插件生态信号，尚缺代表性学生访谈 |
| 复习不能只看摘要 | RemNote、MarginNote 将材料与练习连接；检索练习实验支持主动回忆 [S14,S15,S18] | 自己先回答，再看提示/答案与出处 | 教学方法有研究支持；不证明 AI 出题有效 |
| 学习资料不能被锁在软件里 | MarginNote 用户报告卡片导出时链接内容丢失；Reader 提供多种导出 [S8,S19] | 导出实际文字与图片，附来源；不能只导出应用内链接 | 明确案例；不推断相关产品现版本仍有同一缺陷 |

最值得验证的用户价值：**减少找原文、反复复制和重复整理的时间，同时帮助用户发现自己哪里没理解。** 自动摘要、思维导图和闪卡是手段，不能把生成数量当学习成效。

## 推荐的完整功能结构

### 1. 材料库与学习主题

沿用现有文献条目、分类、收藏、回收站、DOI/RIS/PDF 导入。允许教材没有 DOI，作者/出版物等字段不成为打开学习的门槛。默认提供继续阅读、最近材料、搜索与导入，管理操作按需展开。

后续增加“学习主题”：例如线性代数、某篇论文的复现、某课程考试。一份材料可属于多个主题；主题绑定材料及学习笔记，不复制 PDF。不复用产品现有“项目”一词：项目已具有工作目录和会话含义。

### 2. 阅读和理解：第一优先级

左侧原始材料，右侧复用聊天。章节目录、搜索、批注按需打开；返回材料库保留位置和筛选。避免同时常驻材料树、目录、笔记、聊天和管理资料五栏。

选中一段后提供解释、翻译、追问、记笔记。解释可请求更简单、举例、前置概念、逐步推导；翻译保留原文与术语。框选公式/图表提供原图加邻近正文，不能把普通文本抽取宣称为可靠公式理解。

提问范围明确显示为选中内容、当前章节、整份材料或所选材料。整书问答是检索，不声称每轮逐字读取整本书；章节未解析完应说明覆盖范围。当前片段可用时不应等待整本书索引结束。

教材页码同时处理 PDF 物理页与书内印刷页码；章节导航不应假设两者一致。扫描件按页 OCR，保留 OCR 状态与原图；低置信文字需要用户复核。

### 3. 学习笔记与证据：第一优先级

一条笔记可包含自己的理解、多个原文片段、回答摘录。明确区分原文、AI 解释、用户修订。用户可以从笔记回到确切页内位置；正文检索结果、聊天引用和笔记引用使用同一种来源定位。

提供按章节与主题整理、全文搜索、Markdown 导出。AI 回答保存为笔记时记录来源消息 ID 和来源版本，不能只有脱离出处的副本。不要另造一个平行富文本编辑器：先核对现有 Notes 的公开接口与编辑能力。

### 4. 自测与复习：第二优先级，但属于学习闭环

从选定章节/笔记生成少量可编辑题：解释概念、举例与反例、比较两个概念、公式适用条件、简单迁移题。先尝试作答，再请求提示，最后展开参考答案与原文。用户可以标记没懂，并回到相关段落。

所有题目绑定来源和生成版本，保存前允许修改。不要以一次 AI 判分展示精确“掌握度”；先显示已练、待复习、用户标记困难等可解释状态。将计算题正确性与语言表达分开，答案无法核对时提示复核。

先支持手动自测、困难项复习和可迁移导出；间隔重复调度有真实使用需求后再加。Anki 首期可用文本格式导出文字卡，含图卡另行验证，不能宣称完整无损兼容。

### 5. 跨材料学习：第三优先级

同一概念在教材和论文中如何表达？两篇文章的假设、方法、结论是否一致？提供带证据的对比表，每格绑定来源。缺失写未找到，矛盾并列呈现，摘要级证据不能当全文证据。

主题大纲优先于大图谱；自动关系只作为建议。外部搜索需要显式进入扩展阅读，网络来源与用户材料分开标识。

## 架构建议：围绕来源和学习产物演进

### 数据对象及唯一归属

| 对象 | 建议内容 | 负责人 |
|---|---|---|
| 材料条目 | 标题、书目资料、标签、分类、回收站 | 现有 reading Rust 领域 |
| 附件版本 | attachmentId、contentHash、文件位置、类型；保留旧版本 | reading 领域；先一条目一附件也可有稳定版本 ID |
| 文本块与位置 | 页索引、印刷页标签、章节、文本、多个矩形、抽取器版本 | 文档处理能力；索引可重建 |
| 来源引用 | 材料、附件版本、片段 ID、引用原文、定位信息 | 由文档来源创建，聊天和笔记只引用 |
| 学习笔记 | 用户内容、多来源引用、可选生成消息 ID | 先核对既有 Notes 能否承接；迁移完成后仅留一个写入负责人 |
| 学习主题 | 材料关系、学习目标、笔记关系 | reading 内真实出现该用例后增加 |
| 自测题与练习记录 | 题目、参考答案、证据、用户尝试、修订版本、复习状态 | 学习能力；与聊天消息分开 |
| 对话及消息 | 消息、运行时、流式状态、工具结果 | 现有 chat，Study 只持有关联 ID |

这是逻辑模型，不要求一行对应一个服务或目录。初期在现有 reading 模块扩展，禁止为了表格创建 Service/Manager/Controller 套层。

### 三条关键路径

1. **打开材料**：界面 → 已有 reading 入口 → 打开本地原件并恢复位置；当前页可读后，独立的文档处理任务继续抽取/索引。抽取按 `contentHash + parserVersion` 缓存，取消与重启恢复由任务持有者管理。
2. **提问**：界面提交问题、范围、选区 → Study 问答入口生成本轮来源快照 → 现有检索能力返回文本和位置 → 现有 chat 发送 → 回答绑定证据映射。Study 负责范围与材料准备，chat 负责发送、停止、重试，不转移消息所有权。
3. **自测**：用户选择章节/笔记 → 学习入口生成题目草稿和证据 → 用户修订保存 → 作答/提示/反馈 → 练习记录更新；来源不变时可复用题目，不每次打开重新生成。

引用不能只编码为 `#reading-page-3`。建议稳定地关联 `(sourceId, attachmentVersion, chunkId)`，显示编号只是本轮表现；每轮保留证据映射与检索范围快照，防止切文档、切模型或后续工具调用覆盖编号。旧页码链接继续可读，标为页级定位，不能伪装成已经核验的段落证据。

程序可以检查引用 ID 是否存在、引文是否来自提供的片段、页码与版本是否匹配；程序不能由此证明模型的解释正确。超出原文的举例、推导要明确标识。教材释义可以结合一般知识，但不能伪造“书中指出”。

### 存储与一致性

先不强制全量数据库迁移。当前条目与原 PDF 保留；为附件引入稳定标识，为索引添加可重建缓存。出现跨材料检索、题目调度和多窗口写入需求时，再测量是否把结构化元数据迁入 SQLite；沿用现有技术栈，不新增数据库服务。

保存从整对象覆盖逐步收敛到带预期 revision 的领域更新；Rust 在同一写入临界区检查 revision 并应用变更。冲突需要可恢复结果，不能靠时间戳覆盖。窗口队列仍负责未保存草稿与顺序，后端负责持久不变量。

索引不是第二份资料库：原件由 reading 持有，索引仅引用来源与版本。配置模型、OCR 或 embedding 前说明哪些数据会发往供应商；本地保存不等于全程离线。无 embedding 时仍应支持基本关键词检索和当前片段提问。

迁移保留旧 document ID、notes、conversationIds 和原 PDF；新格式验证成功后才切换读取，保留回滚备份。不要把现有 WebDAV 手动版本备份扩张为 Study 自动同步承诺。

## 实施顺序与完成条件

| 阶段 | 完整用户结果 | 主要工作 | 验收重点 |
|---|---|---|---|
| A：可靠精读 | 打开论文/教材，问一个段落，检查原文，保存理解，下次继续 | 版本化来源、多区域锚点、章节范围、渐进抽取、学习笔记导出 | 原文可见后能操作；切文档/停止无迟到污染；引用能准确回跳 |
| B：学会与复习 | 从章节生成少量自测，先作答再看答案，回到薄弱点 | 题目草稿、来源、用户修订、练习历史；扫描件与图表能力逐步扩展 | 题目与答案有可核验依据；失败保留草稿；不虚报掌握度 |
| C：主题学习 | 多份材料解释同一主题，整理共识和差异 | 学习主题、多材料范围、证据表、跨来源笔记 | 未提供材料不可混入；缺失和矛盾可见；每格可追踪 |
| D：生态与规模 | 大库可找回、资料可带走、可与既有工具配合 | Zotero 互通、BibTeX/CSL JSON、可选复习调度、性能优化 | 导出内容和附件可用，迁移不丢关联；按实测决定优化 |

阶段 A 就应涵盖中文教材和英文论文，不能只拿单篇英文 PDF 做演示。OCR 可以按当前页/章节增量加入，勿把整书高质量 OCR 变成所有用户的启动前置条件。

暂缓：全功能 Word 插件、自动系统综述、多人实时协作、双向云同步、强制知识图谱、自动整书出题与学习排行榜。

## 如何验证，而不是只看演示

建立经授权的小型材料集：英文双栏论文、中文教材、带公式的教材、扫描章节、含表格图注的论文、长书和同一书的新旧版本。每类至少覆盖可抽取与失败/部分失败情况。

- 人工标记问题及证据位置，分别测检索命中、来源定位、答案支持度，不能只测有没有引用编号。
- 验证跨行/跨栏/跨页选择、印刷页码偏移、缩放、重新打开和文件版本变化。
- 无网络、供应商失败、取消索引、离开页面、重启、保存冲突均能恢复，不丢用户笔记。
- 验证只有当前章节就绪时仍可提问，未覆盖章节不虚报已读。
- 实机记录首个可读页面耗时、搜索延迟、峰值内存、每次模型成本；先测基线再设预算，本轮没有性能数值。
- 先与 5–8 名学习者做形成性验证，涵盖教材自学、论文阅读与考试复习。让他们用自己的材料完成“理解一个难点、隔天找回、解释并举例”，观察过程；人数建议不构成统计研究设计。
- 自测价值通过后续无提示解释/迁移任务观察，不能以当天答题分数或聊天时长代替学习成果。

实施时再制定必要的行为测试，遵守 test-audit；本轮未修改或运行测试，未构建/重启桌面应用。
