# Issue #62：超限会话压缩与恢复

本记录描述缺陷证据和本次实现取舍；工程规则仍以 [统一工程规范](../engineering-standards.md) 为准。

## 修复前复现

在基线 `2d6f4551` 增加真实 `run_agent_loop` → OpenAI-compatible HTTP 请求边界测试。十组约 22KB 历史正文，模拟网关拒绝超过 50KB 的请求，小请求正常摘要/回答。此字节限制仅为合成接受规则，不等同真实 token 限制。

- 通用 MaaS 400：摘要请求依次为 210106、210106、210106 bytes，随后发送 231076 bytes 原历史，失败。
- 明确上下文超限：摘要请求为 210106、187024、163942 bytes，随后仍发送 231076 bytes 原历史，失败。
- 两个测试均在「当前问题应恢复成功」断言失败；不是编译或网络错误。普通 HTTP 400 在当前传输层不会重试三次，重复发生在摘要业务层。

## 上游对照与复用

核对 [Pi 1.1.0 源码快照](https://github.com/earendil-works/pi/tree/ee409a85f6ad92bf8c6ab8ed735c6cd24f2e749e)（MIT）与 [ZCode 固定快照](https://github.com/zai-org/ZCode/tree/328c1a0c0ffaa5a4f65e8fa199af5e4c20706e5f)（Apache-2.0）。ZCode 快照不是最新版本声明。

Pi 的 `serializeConversation` 将历史转成带角色标签的文本，工具结果截到 2000 字符；`generateSummaryWithUsage` 支持基于已有摘要继续更新，但不限制整体普通文本输入。ZCode 的摘要超限重选扩大保留尾部，也不能保证恢复后的完整请求可用。因此直接照搬任一实现不能解决上面的纯文本回归。

复用 Pi 的文本转录和累计摘要语义，使用 Kivio 已有 Rust 文本投影、摘要请求、取消和检查点交接；在同一 `compaction.rs` 负责人内增加有界分批处理，不引入 TypeScript 运行时或另一套压缩框架。没有直接复制上游源码。

## 行为与边界

- 常规能装入预算的摘要保留原有结构化路径；超大摘要通过文本分批，每批预算计入系统提示、摘要指令、已生成摘要和输出预留。
- 超大单条文本按 UTF-8 边界拆给摘要模型；原始消息及最终保留的工具调用/结果结构不拆。
- 每段成功后才推进覆盖位置；全部选中历史成功处理后才返回完整检查点，中途失败或取消不提交部分摘要。
- 网关通用 400 不全局等同超限；独立超限证据下允许有限缩减，其他确定性错误停止。
- 自动压缩失败或暂停不再放行本地已知超过硬输入上限的原始请求。提前压缩阈值与硬输入上限分别处理，正常仍能装入的请求不因此中断。
- 原始聊天记录保留，继续沿用现有检查点序列化和重放。若系统提示或必须保留的最新组本身无法装入，则明确停止而不是伪造成功。

## 再次审查后的修正

再次审查发现初版仍有三个缺口；先建立永久失败回归，再对照同一固定 Pi/ZCode 源码修复：

1. **可选压缩暂停与必要恢复分离。** ZCode 自动失败计数只阻止可选 auto，reactive 独立且成功清零；Kivio 适配为本地硬预算压力也能触发一次有界必要恢复。暂停状态不再使后续健康请求永久失去恢复机会，失败仍不发送超大原历史。
2. **按真实工具集合算预算。** planning 传入实际工具快照，synthesis 传空集合；同一集合贯穿触发、摘要、摘要后检查和硬预算，不再误算未发送的工具定义。
3. **分批输出为下一批留空间。** Pi/ZCode 没有可直接复制的完整fold算法。Kivio 在现有负责人内按当前批次预算减固定开销，将剩余空间分配给累计摘要与新片段；网关缩小额度后重算输出上限。如果已有摘要不再适配，在独立重启次数和总请求次数约束下从原选中历史重来，不截断、跳过或提交部分摘要。

前四项永久回归修复前均失败：无工具总结与暂停恢复被误阻断，长摘要及缩水场景分别在1/2次请求后失败。修复后均通过；另覆盖首批已有摘要后才被网关要求缩小的情况。最终 `chat::` 验证：1129 passed / 0 failed / 2 ignored；五项针对性回归全通过，四个改动 Rust 文件格式检查与 diff 检查通过，独立复核无剩余阻断。此次仍未执行真实网关或原生桌面重启验证。
