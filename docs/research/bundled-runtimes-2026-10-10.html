Kivio 内置 Python / Node.js 调研

2026-10-10 · 参考对象按 Codex 桌面应用理解 · 本轮只调研，未修改运行逻辑或安装任何新环境。

推荐：安装包附带可独立运行的 Python、Node.js/npm/npx、uv，以及少量常用处理库。基础能力安装后离线可用；扩展依赖写入 Kivio 管理目录；项目明确指定的解释器、虚拟环境和 CLI 路径继续优先。不要把“首次使用时下载 Python”当作免配置的基础方案。

2. Kivio 当前缺口

  • tauri.conf.json 目前打包 skills、plugins、licenses 和 OCR sidecar，没有 Python/Node 资源。
  • native_tools/shell.rs 在宿主系统执行命令；目前补充启用插件的 bin 路径，尚无自带解释器。
  • PDF、DOCX、XLSX 技能明确要求本机处理工具可用；仅放入 Python 仍会遇到缺少 openpyxl、pypdf 等问题。
  • external_agents/installer.rs 已有缺 Node 时尝试 winget/Homebrew 的逻辑。它属于安装宿主环境，仍依赖安装器、网络和权限；内置环境应成为优先可用的选项，避免继续触发这条补安装路径。
  • MCP、插件 hooks、CLI、PTY 终端各自启动进程；只在 Agent 的 bash 中改 PATH 不能解决其他入口。
  • 当前 release 支持 macOS Apple Silicon 与 Windows x64；首批运行包按这两个目标制作。Windows 安装器及 portable ZIP 均要带齐资源。

4. 接入方式与唯一归属

建立一个真正负责运行环境的 Module：读取运行包清单、解析应用资源与可写缓存路径、校验运行包状态，并生成各类子进程使用的环境。把现有 PATH 补全逻辑与其组合，保持用户 CLI 探测、身份变量清理和插件规则各有归属，不新建多层转发。

  1. 分发：在 CI 获取固定版本官方资源，校验 SHA-256，按目标平台准备并打包；保留解释器和第三方依赖的许可证。应用基础运行环境只读，随应用版本更新。
  2. 扩展：在应用数据目录存放版本化的扩展 venv、npm prefix 和缓存。需要创建 venv 时在最终目录创建，不能把开发机 venv 原样搬进安装包。基础解释器明确绑定；避免 uv 自动下载另一个 Python。
  3. 选择：Kivio 自有文档技能明确使用受管理解释器；项目显式配置的解释器、venv、CLI 路径优先；无配置、无本机环境时使用内置环境。系统有 Python 不代表系统 Python 有基础库，不能仅检查可执行文件是否存在。
  4. 覆盖：让 Agent shell、MCP 启动、插件 hooks、CLI 探测与安装、内置终端共同使用该环境规则，只改变 Kivio 及其子进程，不写用户全局 PATH。
  5. 模块导入：Python/Node 均验证实际业务库导入；Node ESM 不能靠 NODE_PATH 保证导入成功，技能脚本需使用明确的模块根目录、引导入口或受管理包项目。
  6. 模型认知：工具说明和技能写明解释器、已安装包、可写扩展目录和命令入口；保留宿主 Python 安装保护，不让模型反复安装已有库。

受管理运行环境不等于沙箱：当前命令仍在宿主执行，文件权限和工具审批语义不因“内置 Python”改变。Windows 的 python/python3、npm/npx.cmd 与 PowerShell 启动方式，以及 macOS Python 扩展与 Node 的签名/JIT 权限，都需要针对真实发行包确认。

5. 分发取舍

方式评估
基础环境随安装包附带推荐。初次使用与离线使用都可用；代价是安装包变大，升级需维护运行包版本。
首次使用时自动下载缩小应用初始包，但基础功能仍可能被网络、代理、下载失败阻塞；不适合作为本需求的唯一方案。
Homebrew / winget 自动装系统环境可作用户主动选择的路径，但仍有安装器和权限前提，也改变宿主环境，无法提供一致的基础文档能力。

目前没有制作 Kivio 候选运行包，不能给出可信的安装包增量。下一步应先对两种发行平台做最小运行包样品，分别记录下载、解压、打包后的增量，以及导入和首个任务耗时，再决定是否增加大型原生工具。

6. 验收标准与实施次序

先完成 Python/Node 基础包与文档库，再统一进程接入和技能说明，最后补扩展包安装及环境状态页。验收必须在没有系统 Python/Node、没有 Homebrew/winget 辅助的干净机器上进行，不能只验证开发机 npm run dev。

  • 从 Finder / Explorer 打开发行应用；离线导入基础库、读取 PDF/DOCX/XLSX、生成可打开的文档与图表。
  • Agent、Node/Python MCP、插件 hooks 和内置终端均实际执行；依赖未预装的 MCP 需联网取包时，明确区分运行时可用与包下载失败。
  • 含中文与空格路径、只读安装目录、移动后的 Windows portable ZIP 均可运行。
  • 项目已有 venv/Node 配置不被覆盖；追加包不会破坏基础库，也不会写入系统 Python。
  • 从旧版升级后缓存不引用已删除的解释器；下载或扩展安装中断可恢复，错误指向具体缺失资源。
  • 检查 macOS DMG、Windows NSIS 与 portable ZIP 的实际运行资源；Windows 实机验收是必要项。
