# Kivio v4.0.0 之后的审查修复清单

审查基线为 v4.0.0（822d744e）。修复基于 c3617f08 以及当时已有的工作区改动。

| 问题 | 修复后的行为 | 验收证据 |

| 热缓存持续保留长会话 | 最多保留最近 4 个窗口，估算总量上限 24 MiB，空闲 5 分钟过期。窗口超额时跳过缓存；若传入的是完整历史，则预取阅读位置附近的窗口 | 40 个窗口只保留最近 4 个，另测单窗超额和组合超额。[实现](../../src/chat/conversationWarmCache.ts) |
| 旧版长会话拖慢侧栏首次显示 | 已有索引行的旧布局先显示列表，前台版本探测每个文件最多读 8 KiB。后台从原始文件校正元数据，发布前重新核对文件身份 | macOS 桌面冷启动读入带 4.48 MiB 原生历史的旧文件，在 revision 仍为 0 时校正了标题、预览和条数。原文件 SHA-256 保持一致。[实现](../../src-tauri/src/chat/storage/conversations.rs) |

| 外部 CLI 额度页没有可显示记录时无法恢复 | 区分扫描失败和无额度，页面内可重试扫描、刷新账户 | 375 像素宽的 Chromium 模拟所有查询失败，查看各项原因后刷新，成功返回 75% 余额。[实现](../../src/settings/UsageLimitsPanel.tsx) |

## 回归结果

前端 392 个文件、3,463 项测试通过。Chromium 浏览器回归 19 项通过。桌面 Rust 库 3,382 项通过，Grok 实机探针另外手动执行通过。SDK 单元与集成测试合计 239 项、独立 SDK 消费端 183 项通过。前端生产构建、前后端协议一致性、TypeScript、ESLint、架构检查、桌面资源清单和图标检查通过。

macOS 测试版使用隔离的数据目录运行。Antigravity 离线协议对端使旧会话失效后，应用补回可见历史一次，再次重启时继续使用已保存的新会话。

## 验证边界

- 15.6 ms 和 1.7 ms 测的是历史一致性检查。首次打开没有 SQLite 投影的会话仍需要读取原始 JSON。整个侧栏索引遗失时也仍需从文件重建。
- 缓存的 24 MiB 是按对象和字符串估算的预算。会话窗口本身可以显示超过该预算的内容。
- Gemini 和 xAI 服务端协议通过本机 HTTP 对端验证。Grok CLI 默认模型容量通过本机安装的 CLI 读取。Windows 文件身份代码交叉编译通过，Windows 桌面仍待实机验证。
- 专家权限迁移根据存储格式识别 v4 白名单和后续开发版偏好。如果开发版已将旧配置重写为偏好格式，原始权限语义没有单独留存。

## 第二轮复查

- **切回长会话。** 缓存满四项时，恢复中的会话会一直保留到版本核对结束。Chromium 依次打开 A、B、C、D、E 再切回 A，已显示最后一条消息，版本游标恢复成功，窗口读取次数没有增加。完整历史超过预算时，缓存仍按阅读锚点预取较小窗口。
- **旧文件版本。** 版本字段必须读到完整的 JSON 值及其分隔符。若 8 KiB 边界落在数字中间，列表保留待校正的索引，后台读取完整文件；请求权威版本的入口会回退到完整读取。隔离的 macOS 测试应用将旧索引的版本 4 和错误标题校正为正文中的版本 42 和实际标题。
- **外部 CLI。** Grok 默认模型的上下文分母来自实际会话。ACP 模型目录和选中通知可以早于握手响应到达。按 T3 Code 的协议记录回放这一顺序后，只报告已用量的轮次也能取到本会话所选模型的容量，其他会话的选中通知不会覆盖它。额度页同时展示成功的读数和其他账户的失败原因，刷新成功后移除对应提示。375 像素宽的 Chromium 同时显示 Codex 剩余 75% 和 Claude 登录提示，刷新成功后显示两张额度卡。
- **Grok 直连。** 在本机 HTTP 回放中，JSON 和 SSE 都保留截断回复的最后一段正文，下一次请求仍按原顺序携带搜索项和推理密文。未完成的本地函数调用保留截断状态。
- **专家。** 独立窗口读取该会话的技能目录，与主窗口共用白名单过滤。新建专家对话时，只复用冻结配置和知识库挂载归属都与新对话一致的空白会话。macOS WebView 调用实际创建和更新命令，验证了编辑白名单后新会话使用新配置，重新打开旧会话仍保留原配置。

本轮回归通过前端 3,467 项、桌面 Rust 库 3,391 项（默认跳过 61 项）、SDK 全功能配置 308 项和独立 SDK 消费端 184 项。默认跳过的 Grok 实机握手另行执行通过。前端生产构建、TypeScript、ESLint、架构边界和 Rust 格式检查通过。
